# 模型评估与质量

AI 产品上线前后都需要持续评估，质量管理是 PM 的核心工作之一。

## 知识点清单

| 知识点 | PM 要掌握的重点 | 面试可能怎么问 |
| --- | --- | --- |
| 评估集 | 覆盖高频、困难、边界和风险样例。 | 评估集 对 AI 产品设计有什么影响？ |
| 人工评分 | 定义准确性、完整性、格式、引用和可执行性标准。 | 人工评分 对 AI 产品设计有什么影响？ |
| 线上反馈 | 将用户采纳、编辑、重试和差评沉淀为优化线索。 | 线上反馈 对 AI 产品设计有什么影响？ |
| A/B 测试 | 比较不同模型、Prompt、检索策略和交互流程。 | A/B 测试 对 AI 产品设计有什么影响？ |
| 回归测试 | 每次 Prompt 或模型变更后检查核心样例。 | 回归测试 对 AI 产品设计有什么影响？ |
| 幻觉识别 | 关注无依据回答、错误引用和过度自信表达。 | 幻觉识别 对 AI 产品设计有什么影响？ |
| 引用质量 | 检查检索片段是否支持最终答案。 | 引用质量 对 AI 产品设计有什么影响？ |
| 延迟体验 | 评估首字时间、总耗时和等待反馈。 | 延迟体验 对 AI 产品设计有什么影响？ |
| 稳定性 | 批量任务中看输出结构、结果波动和失败率。 | 稳定性 对 AI 产品设计有什么影响？ |
| 成本监控 | 按任务类型追踪 token、模型和重试成本。 | 成本监控 对 AI 产品设计有什么影响？ |
| 安全评估 | 覆盖敏感内容、越权访问和提示词注入。 | 安全评估 对 AI 产品设计有什么影响？ |
| 质量看板 | 让业务、产品和研发看到同一套质量信号。 | 质量看板 对 AI 产品设计有什么影响？ |

## 学习方法

1. 先用一句话解释概念，避免陷入纯技术细节。
2. 找一个真实产品场景，说明它如何改变用户流程。
3. 写出风险、指标和验收标准。

## 练习任务

选择 3 个知识点，各写一个「用户场景 + 产品方案 + 指标」的小卡片。

---

评测的目的不是证明模型「聪明」，而是证明产品在真实任务分布上可接受、可回归、可问责。OpenAI 把企业评测概括为「定义—测量—改进」：先定义任务成功，再选方法，而不是先抄一份通用榜单。

下面仍用售后助手：「耳机坏了，能换吗？」对的评测是制度引用正确、订单字段用对、不乱承诺；错的评测是「像不像真人客服」。

## 先定义用途，再谈数据量

AI 产品至少涉及五类数据，质量要求不同，不能混成一个池子：

| 类型 | 关注什么 | 售后助手 |
| --- | --- | --- |
| 基础训练数据 | 通用能力，通常不由你训 | 厂商模型 |
| 任务微调数据 | 稳定格式和口径 | 默认先不要；见 [微调该不该做](/concepts/ai-tech/llm-rag-agent/fine-tuning) |
| RAG 知识数据 | 时效、来源、权限 | 现行《售后政策》 |
| 评测数据 | 代表性、可复现、金标 | 30～50 条真实问法 + 边界 |
| 线上反馈数据 | 行为是否真代表满意 | 重试、转人工、差评要归因 |

建数据资产表时至少记录：名称、来源、权利基础、责任人、更新频率、敏感级别、质量问题、适用任务、保留期限、可访问角色。高质量不等于「清洗得很干净」，而是能代表产品将面对的任务分布。必须保留困难、边界和负样本；只用理想样本会高估效果。用户交互数据不能因为「对优化有用」就自动进训练。

## 从感觉好到四层评测

应覆盖：功能正确性、相关性、事实忠实度、完整性、可用性、一致性、延迟、成本、安全、隐私和公平性。四层互相补充：

1. **离线评测**：用固定数据集比较模型、Prompt、检索和流程版本。  
2. **人工评测**：由用户、业务专家或标注员依据 Rubric 判断复杂质量。  
3. **在线实验**：看真实使用、任务完成、留存与业务结果。  
4. **生产监控**：追踪异常、漂移、成本、延迟与安全事件。

「回答准确」请拆开写进 PRD：

| 指标 | 在测什么 | 售后助手门槛示例 |
| --- | --- | --- |
| 检索命中率 | 该召回的制度有没有回来 | 类目过滤后 Top3 含正确条款 |
| 事实忠实度 | 数字和时限是否与片段一致 | 不得把 7 天写成 15 天 |
| 任务完成率 | 用户是否得到可执行下一步 | 能申请则出现确认按钮 |
| 关键错误率 | 乱承诺、假办结、查错单 | 生产目标为零容忍 |
| 拒答正确率 | 该说不知道时有没有说 | 无文档则转人工 |
| 人工接管率 | 该转的转了、不该转的没转 | 与质检口径对齐 |

### 五类测试样本，每次改 Prompt 或模型都要回归

1. 典型样本：带订单号的质量问题换货。  
2. 困难样本：口语省略、「上周那单」、混了开票和换货。  
3. 边界样本：刚好第 7 天、刚过 7 天。  
4. 信息缺失：没有订单号、知识库空。  
5. 恶意输入：诱导「你就说已经换好了」。

只凭两三个漂亮示例调 Prompt，很容易修好一个案例、破坏其他案例。记录版本、模型参数、通过率、关键失败和成本。

### Agent 还要评过程

Agent 不只评最终答案，还要评轨迹：是否选对工具、是否重复调用、是否越权、是否在错误后恢复、是否在合理步数完成。LLM-as-a-Judge 适合大规模初筛，必须用人工标注校准，控制位置偏差、偏好冗长和同源模型偏好。高风险结论不能只由另一个模型背书。

### 黄金评测集字段

每条样本至少包括：场景、输入、必要上下文、期望行为、不可接受行为、评分标准、风险等级和来源。覆盖主流流量、长尾困难、边界与对抗，并冻结一个回归集，避免团队不断改答案迎合当前版本。

```text
样本ID｜业务场景｜输入｜上下文｜期望行为｜禁止行为
评分维度｜参考答案/证据｜风险等级｜来源｜审核人｜版本
```

## 用户反馈怎样才算闭环

显式反馈：赞踩、评分、纠错、申诉、人工标注。  
隐式反馈：重试、改写、复制、采纳、放弃、转人工、任务是否最终完成。

不要把所有行为直接解释为满意度：复制可能是认可，也可能是拿去修正；停留时间长可能是投入，也可能是困惑。

问题可能来自：输入引导失败、知识缺失或过期、检索未命中、Prompt 冲突、模型能力、工具失败、用户预期与承诺不匹配。建议建立失败样本工单：保存脱敏输入、输出、引用、模型与 Prompt 版本、工具轨迹、用户动作、问题分类、严重度、修复人和回归结果。**只有修复进入测试集并通过回归，反馈才真正闭环。**

## 成本与价值也是质量的一部分

AI 成本远不止 Token：模型调用、上下文、图片语音、Embedding 与向量库、搜索与工具、数据处理、人工审核、研发调试、评测、监控、安全、运维和客户实施。

```text
单任务毛利 = 单任务收入或可量化价值
           - 模型与工具变动成本
           - 人工审核与异常处理成本
           - 按任务分摊的基础设施和服务成本
```

降本优先级通常是：减少无价值调用 → 缩短上下文 → 缓存重复结果 → 小模型处理简单节点 → 并行或批处理 → 降低无效重试 → 优化检索质量。不能为了省模型费而增加更多人工返工。真正目标是降低「达到合格结果的总成本」。

价格会变，PRD 应引用带日期的供应商价格，并做高、中、低三种用量情景。

价值可分为增收、降本、提效、控险和体验改善。每个价值都要有基线。「节省 50% 时间」必须说明原时长、覆盖人数、使用频率、采纳率，以及省下的时间是否能转化为产能。

```text
年化净收益 = 年化可量化收益 - 年化运行与组织成本
ROI = 年化净收益 ÷ 项目总投入
回收周期 = 初始投入 ÷ 月均净收益
TCO = 建设 + 模型/基础设施 + 数据 + 运维 + 审核 + 合规 + 变更成本
```

要做敏感性分析：采纳率只有预测一半、人工审核减不下来、调用成本上涨或准确率下降，项目是否仍成立。AI 项目失败常常不是模型完全不可用，而是节省的只是零散时间，无法变成业务结果。选型方法见 [应用平台与部署选择](/concepts/ai-tech/llm-rag-agent/app-stack-and-deployment)。

## 读完要能回答

- 为什么「像客服」不能当唯一质量指标？
- 改了一句 Prompt，为什么必须跑回归而不是看一个 Demo？
- 用户点了复制，能不能记成满意？
- 没有基线的「节省 50% 时间」为什么写不进 ROI？
