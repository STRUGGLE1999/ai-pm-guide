# 2.2 命名实体识别（NER）

### 2.2.1 NER 是什么？

命名实体识别（Named Entity Recognition，NER）是在文本中定位并分类实体，如人名、机构、地点、时间、金额、产品、疾病、法条等。

```text
“张三于2026年6月在深圳与腾讯签署合作协议。”
```

| 文本片段 | 类型 |
|---|---|
| 张三 | 人名（PER） |
| 2026年6月 | 时间（TIME） |
| 深圳 | 地点（LOC） |
| 腾讯 | 机构（ORG） |

### 2.2.2 为什么 NER 是信息抽取入口？

| 业务 | 可能抽取的实体 |
|---|---|
| 合同审核 | 甲方、乙方、金额、日期、条款 |
| 医疗文本 | 疾病、症状、药物、检查项目 |
| 法律文书 | 案号、当事人、法院、法条、罪名 |
| 客服系统 | 商品、订单号、手机号、地址 |
| 金融风控 | 公司、人物、金额、账户、时间 |

### 2.2.3 BIO 标注体系

NER 常把每个 token 标成：

- `B-XXX`：实体开始（Begin）  
- `I-XXX`：实体内部（Inside）  
- `O`：非实体（Outside）  

| Token | 标签 |
|---|---|
| 张 | B-PER |
| 三 | I-PER |
| 在 | O |
| 深 | B-LOC |
| 圳 | I-LOC |

### 2.2.4 NER 的方法选择

| 方法 | 优点 | 局限 | 适合场景 |
|---|---|---|---|
| 正则 | 精准、可控 | 覆盖有限 | 订单号、手机号、金额 |
| 词典匹配 | 易维护 | 歧义、召回不足 | 药品、机构、术语词库 |
| CRF | 标签转移建模强 | 依赖特征设计 | 传统序列标注 |
| BiLSTM-CRF | 可学上下文 | 长依赖一般 | 中小规模任务 |
| BERT-CRF / Transformer | 精度与迁移性强 | 需标注与算力 | 主流高精度 NER |
| LLM 抽取 | 灵活、Schema 易变 | 成本和格式稳定性 | 原型、低频复杂抽取 |

### 2.2.5 规则 NER：格式稳定的信息先用规则

```python
import re

text = "订单号为202607060001，联系人王小明，手机号13800138000，金额¥2,399.00。"
patterns = {
    "ORDER_ID": r"\b\d{12,20}\b",
    "PHONE": r"\b1[3-9]\d{9}\b",
    "MONEY": r"[¥￥]\s?\d[\d,]*(?:\.\d{1,2})?"
}

entities = []
for label, pattern in patterns.items():
    for match in re.finditer(pattern, text):
        entities.append({
            "text": match.group(), "label": label,
            "start": match.start(), "end": match.end()
        })
print(entities)
```

> 工程经验：**能通过稳定格式精确识别的字段，不要让大模型或深度模型去猜。** 规则与模型混合通常更可靠。

### 2.2.6 Transformer NER 的计算过程

```mermaid
flowchart LR
    A[输入句子] --> B[Tokenizer 切成 token]
    B --> C[Transformer Encoder]
    C --> D[每个 token 分类]
    D --> E[B-PER / I-PER / O]
    E --> F[合并相邻 token]
    F --> G[实体文本、类型、起止位置]
```

### 2.2.7 NER 该怎么评估？

NER 不能只看“单个字预测对不对”，而要看实体级的 Precision、Recall、F1。

真实答案：`深圳电信 / ORG`  
模型输出：`深圳 / LOC`

这既错了边界，也错了类型，通常按完整错误处理。评估时要明确：是否允许嵌套实体？是否允许部分匹配？不同策略会造成不同分数。

### 2.2.8 NER 常见坑

- 标签类型设计过细，但数据量太少；
- “北京大学人民医院”这类嵌套实体没提前定义规则；
- 标注员标准不一致；
- 训练文本正式，上线文本来自 OCR 或语音转写；
- 只标“看起来重要”的实体，忽略业务是否需要它。
