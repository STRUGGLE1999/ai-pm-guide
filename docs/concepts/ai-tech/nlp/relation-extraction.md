# 2.3 关系抽取

### 2.3.1 关系抽取是什么？

关系抽取（Relation Extraction，RE）是识别实体之间的关系，常输出为三元组：

$$
(\text{Subject},\text{Relation},\text{Object})
$$

```text
“马化腾是腾讯公司的创始人之一。”
→ （马化腾，创始人，腾讯公司）
```

### 2.3.2 NER 与关系抽取如何协作？

```mermaid
flowchart LR
    A[原始文本] --> B[NER：找实体]
    B --> C[生成候选实体对]
    C --> D[关系分类 / 联合抽取]
    D --> E[三元组、表格或知识图谱]
```

例子：

```text
“阿里巴巴总部位于杭州。”
实体：阿里巴巴（ORG）、杭州（LOC）
关系：（阿里巴巴，总部位于，杭州）
```

### 2.3.3 关系抽取真正要回答的三件事

| 问题 | 例子 | 解释 |
|---|---|---|
| 有没有关系 | “张三在腾讯工作” | 张三与腾讯有关联 |
| 是什么关系 | “张三创办腾讯” | 是创始人，不只是任职 |
| 限定条件是什么 | “张三曾于2024年担任…” | 时间、职位、是否仍有效都可能重要 |

### 2.3.4 三条技术路线

| 路线 | 方式 | 优势 | 局限 |
|---|---|---|---|
| 规则模板 | 触发词 + 正则/句法 | 快、可解释 | 覆盖有限 |
| 监督关系分类 | 实体对 + 句子 → 标签 | 稳定、可量化 | 需标注数据 |
| 联合/生成式抽取 | 同时输出实体和关系 | 适应复杂句 | 约束、评估更难 |

### 2.3.5 可运行规则示例：抽取任职关系

```python
import re

text = "李华于2025年加入星云科技，担任产品经理。"
pattern = re.compile(
    r"(?P<person>[\u4e00-\u9fa5]{2,4})于(?P<time>\d{4}年)"
    r"加入(?P<org>[\u4e00-\u9fa5]{2,10})，担任(?P<title>[\u4e00-\u9fa5]{2,10})"
)

m = pattern.search(text)
if m:
    result = {
        "subject": m.group("person"),
        "relation": "任职于",
        "object": m.group("org"),
        "qualifiers": {"time": m.group("time"), "title": m.group("title")}
    }
    print(result)
```

### 2.3.6 Schema 设计比“选什么模型”更早、更重要

例如合同抽取不应只说“抽关系”，而要先定义：

| 关系 | 主语类型 | 宾语类型 | 示例 |
|---|---|---|---|
| 签署方 | 合同 | 机构/个人 | （合同A，签署方，甲公司） |
| 金额 | 合同/条款 | 金额 | （合同A，金额，100万元） |
| 生效日期 | 合同 | 时间 | （合同A，生效日期，2026-01-01） |
| 违约责任 | 条款 | 责任描述 | （第8条，违约责任，支付违约金） |

一个关系必须能进入后续数据库、搜索、审核、图谱或报表，否则“抽出来”也没有业务闭环。

### 2.3.7 关系抽取评估

应拆开评估：实体边界、实体类型、关系类型、三元组完整匹配、时间/金额等限定信息。不要只用“看起来差不多”判断效果。
