# 政务与标书

按文档工程做标书和办事辅助，生成必须绑证据，不能虚构资质。

## 背景

这个案例适合训练 AI 产品经理从业务场景出发，而不是从模型能力出发。政府项目除了功能，还要能被招标、验收和审计。

## 用户与痛点

- **目标用户**：投标商务、技术方案作者、政务热线、窗口办事人员、公文岗。
- **核心痛点**：招标文件长、评分点易漏、企业材料散、政策时效和地区适用难判断。
- **AI 机会**：解析、抽取、检索、检查清单；行政判断和资质事实不能编。

## 产品方案

1. 明确输入：招标文件、企业资质库、历史标书、政策文号、地区与时效。
2. 明确处理：工作流按章节推进，每段绑定证据；冲突标红给人。
3. 明确输出：目录、任务分工、章节草稿、偏离表、核验清单。
4. 明确兜底：缺资质就写「材料不足」，禁止补造。

## 指标

- 使用：触发率、完成率、留存。
- 质量：评分点覆盖率、虚假陈述次数、审校修改率。
- 效率：成稿时长、一次通过率。
- 风险：泄密、越权出域、错误行政指引。

## 可写进简历

设计「标书 / 政策辅助」文档工程，强调证据绑定、偏离检查和「提供信息 vs 作出判断」。

---

标书链路：招标文件解析 → 要求与评分点抽取 → 目录与任务分工 → 企业材料检索 → 分章节撰写 → 响应检查 → 偏离表与附件核验 → 多人审校。生成必须绑定证据和模板，不能虚构资质、案例、业绩或参数。条款级审查也可对照 [合同审查助手](/practice/contract-review)。

政务场景包括办事指引、热线、公文辅助、政策检索、执法辅助和风险预警。产品需要处理地区、时效、适用对象和政策层级，区分「提供信息」和「作出行政判断」。涉密、敏感和个人信息按数据分级限制模型、人员和外部服务访问。

政府项目还关注政策目标、部署环境、等保与安全、审计、采购、验收和长期运维。Demo 要转化成可招标、可交付、可验收的能力清单，而不是一次现场生成全文。

## 验收例子

| 用例 | 通过 | 不通过 |
| --- | --- | --- |
| 评分点未覆盖 | 偏离表列出并标红 | 正文假装已响应 |
| 库里没有某证书 | 明确缺失 | 生成「已具备 XXX 认证」 |
| 政策问法 | 带文号、地区、时效 | 把过期文件当现行 |
| 热线办事 | 「这是指引，以窗口审核为准」 | 代替窗口作出准予决定 |

## 面试怎么讲

讲采购角色、等保和数据出域，比讲「用了 RAG」更像政务产品。没有真实项目时，用一份公开招标文件做抽取和偏离表 Demo，并声明未上生产。
