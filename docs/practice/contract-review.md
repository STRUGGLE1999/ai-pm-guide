# 合同审查助手

识别条款风险、给出依据和修改建议。

## 背景

这个案例适合训练 AI 产品经理从业务场景出发，而不是从模型能力出发。

## 用户与痛点

- **目标用户**：业务人员、运营人员、客服/销售/管理者或内部知识工作者。
- **核心痛点**：信息分散、重复劳动、判断成本高、输出质量不稳定。
- **AI 机会**：用检索、生成、工具调用或工作流降低任务完成成本。

## 产品方案

1. 明确输入：用户提供什么材料、系统能读取哪些数据。
2. 明确处理：模型、检索、规则和人工确认分别负责什么。
3. 明确输出：答案、摘要、报告、建议、工单或结构化结果。
4. 明确兜底：失败提示、人工接管、重试和日志。

## 指标

- 使用：触发率、完成率、留存。
- 质量：采纳率、人工修改率、差评率。
- 效率：节省时间、自动处理比例。
- 风险：错误率、越权访问、敏感输出。

## 可写进简历

设计「合同审查助手」方案，围绕用户任务拆解 AI 输入、处理、输出、评估和风险兜底，形成可落地的产品闭环。

---

标书和合同都应按文档工程设计，而不是「把 PDF 丢进聊天框」。一条可验收链路：文件解析 → 要求与评分点 / 风险条款抽取 → 企业材料或历史合同检索 → 分章节撰写或修改建议 → 响应检查 / 偏离表 → 多人审校。

生成必须绑定证据和模板，不能虚构资质、案例、金额或参数。高风险结论采用「AI 定位与提示—法务或商务决策」。政务场景还要处理地区、时效、适用对象和政策层级，区分「提供信息」和「作出行政判断」。涉密和个人信息按分级限制出域。

## 指标

效率看处理时长和一次通过率；质量看条款召回、虚假陈述次数、律师修改率；风险看越权承诺和泄密。Demo 要能转化成可招标、可交付、可验收的能力清单，而不是一次现场生成全文。
