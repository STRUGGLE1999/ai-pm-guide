# Agent 工作流

让 AI 规划步骤、调用工具并在人类确认下执行任务。

## 背景

这个案例适合训练 AI 产品经理从业务场景出发，而不是从模型能力出发。

## 用户与痛点

- **目标用户**：业务人员、运营人员、客服/销售/管理者或内部知识工作者。
- **核心痛点**：信息分散、重复劳动、判断成本高、输出质量不稳定。
- **AI 机会**：用检索、生成、工具调用或工作流降低任务完成成本。

## 产品方案

1. 明确输入：用户提供什么材料、系统能读取哪些数据。
2. 明确处理：模型、检索、规则和人工确认分别负责什么。
3. 明确输出：答案、摘要、报告、建议、工单或结构化结果。
4. 明确兜底：失败提示、人工接管、重试和日志。

## 指标

- 使用：触发率、完成率、留存。
- 质量：采纳率、人工修改率、差评率。
- 效率：节省时间、自动处理比例。
- 风险：错误率、越权访问、敏感输出。

## 可写进简历

设计「Agent 工作流」方案，围绕用户任务拆解 AI 输入、处理、输出、评估和风险兜底，形成可落地的产品闭环。

---

工作流是预先定义的路径，适合步骤明确、需要稳定复现的任务；Agent 由模型根据环境动态决定下一步。自主性增加通常同步增加成本、延迟和错误面，应从能解决问题的最简单结构开始。

口诀：能用一次模型调用解决，就不做工作流；能用确定工作流解决，就不增加 Agent。客服换货咨询 v1 应是固定工作流；只有用户说法很散、工序集合仍封闭时，再外包一层意图路由。模式、记忆与 Skill 见 [Agent、MCP 与多智能体](/concepts/ai-tech/llm-rag-agent/agent-mcp)，拆节点方法见 [工具调用与工作流](/concepts/ai-tech/llm-rag-agent/tool-calling-workflow)。

写操作必须确认。评测既看最终结果，也看是否选对工具、是否越权、是否在步数预算内结束。
