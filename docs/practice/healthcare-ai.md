# 医疗健康 AI

把健康咨询、分诊辅助和临床支持拆开设计，医生最终决策。

## 背景

这个案例适合训练 AI 产品经理从业务场景出发，而不是从模型能力出发。医疗不是「更聪明的客服」，错误成本、数据和责任链都不同。

## 用户与痛点

- **目标用户**：C 端用户（健康咨询）、分诊护士、临床医生、病历质控、随访运营。
- **核心痛点**：非结构化病历难用、分诊排队长、随访重复劳动高、医生检索指南耗时。
- **AI 机会**：结构化、检索证据、生成草稿；不能替代诊断和处方。

## 产品方案

1. 明确输入：主诉文本、影像、检验、授权病历、药品目录。
2. 明确处理：规则管禁忌和权限，检索管指南和说明书，模型管理解和草稿。
3. 明确输出：分诊建议、病历摘要、随访话术、带出处的参考，而不是「确诊」。
4. 明确兜底：高危主诉升级人工、证据不足拒答、模型持续监测。

## 指标

- 使用：触发率、完成率、留存。
- 质量：采纳率、人工修改率、差评率。
- 效率：节省时间、自动处理比例。
- 风险：漏诊相关投诉、越权访问、夸大宣传。

## 可写进简历

设计「医疗健康 AI」方案，区分消费级健康信息与临床辅助，写清医生决策、证据追溯和评测（灵敏度、特异度、亚组差异）。

---

必须先拆产品类型。面向消费者的健康信息应明确不能替代诊断；面向医疗机构的辅助要嵌入临床责任链：谁下医嘱、谁签字、异常谁升级。把两类混在一个聊天框里，合规和信任会一起垮。

## 人、规则、模型怎么分

| 任务 | 适合谁 | 禁止 |
| --- | --- | --- |
| 健康科普、用药说明书检索 | RAG + 生成，带来源 | 给出个体化用药方案并暗示已确诊 |
| 分诊辅助 | 规则（红旗症状）+ 模型理解主诉 | 把胸痛等急症压在机器人里 |
| 病历结构化 | 抽取 + 医生核对 | 静默改写病程记录 |
| 临床决策支持 | 检索指南 + 提示鉴别 | 自动开具诊断或处方 |
| 随访提醒 | 模板 + 确认后发送 | 用营销话术承诺疗效 |

数据要求：合法授权、隐私保护、标准术语、病例代表性、跨机构与跨设备验证。单一医院表现好，不代表能泛化到其他人群、设备或流程。

评测除准确率外，还要看灵敏度、特异度、漏诊风险、亚组差异、医生采纳和临床结果。坚持医生最终决策、证据可追溯、异常可升级、模型持续监测。严禁用营销语言夸大诊断或治疗效果。安全边界见 [安全、合规与权限](/concepts/safety-and-compliance)。

## 验收例子

| 用例 | 通过 | 不通过 |
| --- | --- | --- |
| 用户问「我是不是得了 XX」 | 给信息、建议就医、不确诊 | 「根据您的描述可以确诊」 |
| 红旗症状 | 立即升级人工 / 急诊指引 | 继续闲聊安抚 |
| 病历摘要 | 字段可追溯到原文，医生可改 | 模型编造未出现的阳性体征 |
| 对外文案 | 写清「辅助、不替代诊疗」 | 「AI 医生，准确率 99%」 |

## 面试怎么讲

先说清服务对象和责任人，再说数据能否合法拿到、评测用什么金标、为什么不上全自动开医嘱。没有医院合作时，如实写这是方案或 PoC，不要编临床上线规模。
