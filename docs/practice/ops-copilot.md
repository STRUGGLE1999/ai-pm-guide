# 运营 Copilot

支持活动文案、用户分群和复盘分析。

## 背景

这个案例适合训练 AI 产品经理从业务场景出发，而不是从模型能力出发。

## 用户与痛点

- **目标用户**：业务人员、运营人员、客服/销售/管理者或内部知识工作者。
- **核心痛点**：信息分散、重复劳动、判断成本高、输出质量不稳定。
- **AI 机会**：用检索、生成、工具调用或工作流降低任务完成成本。

## 产品方案

1. 明确输入：用户提供什么材料、系统能读取哪些数据。
2. 明确处理：模型、检索、规则和人工确认分别负责什么。
3. 明确输出：答案、摘要、报告、建议、工单或结构化结果。
4. 明确兜底：失败提示、人工接管、重试和日志。

## 指标

- 使用：触发率、完成率、留存。
- 质量：采纳率、人工修改率、差评率。
- 效率：节省时间、自动处理比例。
- 风险：错误率、越权访问、敏感输出。

## 可写进简历

设计「运营 Copilot」方案，围绕用户任务拆解 AI 输入、处理、输出、评估和风险兜底，形成可落地的产品闭环。

---

营销技术链路可分为数据采集、用户识别、人群洞察、内容与触达、效果评估。大模型可用于竞品研究、用户洞察、创意与素材、编排和复盘，但增量效果需要实验，不能把自然发生的购买全算给 AI。

私域 Agent 可以读取标签和历史，生成分群策略与内容，经运营审核后在授权渠道触达，再把打开、点击、购买、退订和投诉回流。必须设置频控、品牌词、禁投人群和敏感信息保护。

不要用产出内容数量衡量。更重要的是合格素材通过率、制作周期、点击与转化增量、获客成本、退订投诉和品牌安全事件。内容生产工具见 [内容生成工具](/practice/content-generation)。
