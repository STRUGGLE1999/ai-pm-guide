# 教育行业 AI

从错题闭环和教师助手出发，把教学责任留在人这边。

## 背景

这个案例适合训练 AI 产品经理从业务场景出发，而不是从模型能力出发。教育效果不能用生成次数衡量。

## 用户与痛点

- **目标用户**：学生、家长、教师、教研和学校管理者。
- **核心痛点**：错题只拍不练、个性化名不副实、教师备课和批改占用教学决策时间。
- **AI 机会**：识别、结构化、错因分析、出题草稿、学情汇总；教学目标仍由教师设定。

## 产品方案

1. 明确输入：拍题图片、作业文本、知识点树、学情记录、教师目标。
2. 明确处理：识别与判断可模型化；下一题选择应基于掌握状态，而不是「相似题」。
3. 明确输出：错因、针对练习、学习计划、课件草稿，全部可编辑、可否决。
4. 明确兜底：识别失败让学生重拍或手输；超纲或价值观问题转人工教研。

## 指标

- 使用：触发率、完成率、留存。
- 质量：采纳率、人工修改率、差评率。
- 效率：教师备课时长、批改时长。
- 风险：未成年人数据、学术诚信、内容适龄、过度依赖。

## 可写进简历

设计「错题本 + 教师助手」方案，写清掌握状态如何驱动下一任务，以及教师如何查看出处、编辑和否决。

---

错题产品的链路是：图像/文本识别 → 题目结构化 → 答案判断 → 知识点映射 → 错因分析 → 针对练习 → 学习计划 → 效果回测。真正的个性化不是推荐「相似题」，而是基于掌握状态、错误模式和学习目标选择下一任务。拍了十道都做错同一类计算，下一批仍丢同质难题，产品就失败了。

教师 Agent 可辅助备课、课件、试题、批改、反馈和学情分析。目标是释放教师时间并改善教学决策，而不是把教学责任移交给模型。教师应能查看来源、编辑内容、设置教学目标和否决建议。

对内培训场景见 [企业培训助手](/practice/training-assistant)。C 端还要处理未成年人数据、内容适龄、公平可及、学术诚信和过度依赖。效果用知识掌握、迁移能力、教师效率和学生参与衡量。

## 验收例子

| 用例 | 通过 | 不通过 |
| --- | --- | --- |
| 拍题模糊 | 提示重拍或手输，不编造题目 | 识别错题仍生成「标准答案」 |
| 连续同类错误 | 下调难度或换表征方式 | 继续推更难的同型题 |
| 课件草稿 | 带来源，教师可改 | 不可编辑、无法看依据 |
| 作业代写 | 引导思路或拒答 | 直接交可粘贴的全文答案 |

## 面试怎么讲

讲清学生/教师谁是用户、谁付费、掌握状态存在哪、为什么不用纯生成题海。主动提学术诚信和未成年人保护，比只讲「AI 出题」更像教育产品经理。
