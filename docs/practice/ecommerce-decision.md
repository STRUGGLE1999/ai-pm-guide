# 电商选品与智能决策

把硬规则、模型建议和人工确认串成选品与补单闭环。

## 背景

这个案例适合训练 AI 产品经理从业务场景出发，而不是从模型能力出发。电商 AI 的价值在周转和毛利，不在推荐话术是否流畅。

## 用户与痛点

- **目标用户**：选品、商品运营、定价、库存和投放同学。
- **核心痛点**：趋势信号散、竞品和评论难读、补单拍脑袋、定价和库存一改就难回滚。
- **AI 机会**：评论与竞品洞察、候选排序、内容生成；硬约束（毛利、合规、供应）走规则。

## 产品方案

1. 明确输入：销售、库存、退货、评论、竞品、供应周期、合规清单。
2. 明确处理：先规则淘汰，再模型综合趋势与需求，最后人确认。
3. 明确输出：入选/淘汰原因、建议价、补单量、商品文案草稿。
4. 明确兜底：数据不足不给结论；定价库存先建议模式。

## 指标

- 使用：触发率、完成率、留存。
- 质量：采纳率、人工修改率、人机分歧回顾。
- 效率：上市周期、决策时长。
- 风险：违规商品、缺货、滞销、退货。

## 可写进简历

设计「选品 / 补单决策助手」，写清规则淘汰、模型排序和人工确认，并用上市周期、售罄率、周转和退货验收。

---

覆盖选品、趋势洞察、竞品与评论分析、供应商评估、商品内容、定价、库存和投放。选品系统应把数据指标、硬规则、模型判断和人工经验结合：先排除毛利、合规、供应和库存不满足的候选，再用模型综合趋势与用户需求，最后由业务人员确认。

小单快反的价值来自需求信号、柔性供应链和快速补单的闭环，不是单一推荐算法。指标要贯穿上市周期、首单量、售罄率、补单准确、库存周转、缺货和退货。

对于定价、库存或预算，先以建议模式上线，记录人机分歧与事后结果；只有数据稳定、边界明确且可回滚时提高自动化。模型的解释可帮助决策，流畅理由不是因果证据。「因为评论里都在说显白」不能单独撑起一次大补单。

## 验收例子

| 用例 | 通过 | 不通过 |
| --- | --- | --- |
| 毛利为负的爆款候选 | 规则直接淘汰并说明 | 模型因「趋势好」推荐上架 |
| 评论洞察 | 带来源评论片段 | 编造不存在的槽点 |
| 补单建议 | 给区间、假设和库存约束 | 直接改库存且不可撤 |
| 商品文案 | 品牌词和禁词过滤 | 出现未证实的功效承诺 |
