# 企业培训助手

把课程资料转成测验、学习路径和答疑助手。

## 背景

这个案例适合训练 AI 产品经理从业务场景出发，而不是从模型能力出发。

## 用户与痛点

- **目标用户**：业务人员、运营人员、客服/销售/管理者或内部知识工作者。
- **核心痛点**：信息分散、重复劳动、判断成本高、输出质量不稳定。
- **AI 机会**：用检索、生成、工具调用或工作流降低任务完成成本。

## 产品方案

1. 明确输入：用户提供什么材料、系统能读取哪些数据。
2. 明确处理：模型、检索、规则和人工确认分别负责什么。
3. 明确输出：答案、摘要、报告、建议、工单或结构化结果。
4. 明确兜底：失败提示、人工接管、重试和日志。

## 指标

- 使用：触发率、完成率、留存。
- 质量：采纳率、人工修改率、差评率。
- 效率：节省时间、自动处理比例。
- 风险：错误率、越权访问、敏感输出。

## 可写进简历

设计「企业培训助手」方案，围绕用户任务拆解 AI 输入、处理、输出、评估和风险兜底，形成可落地的产品闭环。

---

对内培训可以把课程资料转成测验、路径和答疑；对 C 端教育产品，错题链路通常是识别 → 结构化 → 判断 → 知识点映射 → 错因分析 → 针对练习 → 计划 → 回测。真正的个性化不是推荐「相似题」，而是基于掌握状态和错误模式选择下一任务。

教师或内训讲师应能查看来源、编辑内容、设置目标和否决建议。产品目标是释放备课和答疑时间，而不是把教学责任交给模型。还要处理未成年人数据、内容适龄、公平、学术诚信和过度依赖（对内则是考题泄漏和过期课件）。

效果用知识掌握、迁移、讲师效率和参与度衡量，不能只看生成次数。更多行业要点见 [AI 产品专题](/concepts/ai-product-topics) 教育一节。
