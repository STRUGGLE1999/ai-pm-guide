### 题 1：字节跳动飞书智能助手如何设计Agent工作流编排以降低人工干预率？

> 🏢 **真题来源**：字节跳动 · 飞书智能助手 / Agent 产品面经

::: info 🎯 核心考点与破题关键
- **考点实质**：考察对Agent工作流中任务分解、工具调用与异常处理的设计能力，核心是平衡自动化与人工兜底。
:::

::: tip 💡 参考回答示范
> “我在飞书智能助手项目中，负责设计会议纪要生成Agent的工作流。首先，我们将用户请求拆解为「日程查询→会议录音转写→摘要生成→待办提取→消息推送」五个步骤。每个步骤对应一个工具调用，并设置超时和重试机制。为了降低人工干预率，我们引入了置信度阈值：当转写置信度低于0.8时，自动触发人工校对队列；当摘要生成结果与原文相似度低于0.6时，重新生成一次。样本是过去一个月内5000次会议纪要请求，口径是人工干预率（即需要人工修改或重新触发的比例）。我们通过A/B测试对比了不同阈值下的干预率和用户满意度，最终将干预率从35%降至18%，同时满意度保持在4.5分以上。关键点在于：每个环节的输出都要有质量评估指标，并设计降级路径，比如转写失败时直接推送录音链接并提示手动上传。”
:::

::: warning ⚠️ 连环追问与高分续答
- **追问 1**：如果工具调用频繁超时，如何调整工作流？
  - **续答**：我会先分析超时原因：如果是下游服务不稳定，增加重试次数和退避策略；如果是请求参数不合理，优化参数构造逻辑。同时，设计并行调用和缓存机制，比如日程查询和录音转写可以并行，转写结果缓存1小时。样本是超时日志的1000条记录，口径是超时率，目标是将超时率控制在5%以内。
:::

::: details 🛠️ 换成你自己的项目时改这三处
1. 将会议纪要场景替换为客服工单处理，步骤改为「工单分类→信息抽取→知识库检索→回复生成→人工审核」。
2. 调整置信度阈值和相似度阈值，根据业务对准确率的要求重新设定，并说明依据。
3. 增加成本考量，比如工具调用次数与token消耗的权衡，给出优化前后的成本对比。
:::

### 题 2：阿里巴巴RAG检索中如何设计切分策略以平衡召回率与生成质量？

> 🏢 **真题来源**：阿里巴巴 · 通义千问企业知识库 / RAG 产品面经

::: info 🎯 核心考点与破题关键
- **考点实质**：考察对文档切分粒度、重叠窗口、元数据增强等策略的理解，核心是召回内容与生成答案的相关性。
:::

::: tip 💡 参考回答示范
> “在通义千问企业知识库项目中，我负责设计文档切分策略。我们处理的是产品手册和FAQ，平均文档长度2000字。最初按固定长度500字切分，重叠100字，但发现召回片段经常截断关键信息。后来改为基于语义的切分：先用小模型识别段落边界，再按标题层级切分，确保每个片段包含完整语义单元。对于表格和列表，单独处理并保留表头。样本是1000份文档，口径是召回率（人工标注的相关片段被召回的比例）和生成答案的准确率。我们对比了三种策略：固定长度、按段落、按语义，结果显示按语义切分的召回率达到92%，比固定长度提升15个百分点，生成答案准确率从78%提升到85%。同时，我们为每个片段添加了元数据（如文档标题、章节），在检索时用于过滤。”
:::

::: warning ⚠️ 连环追问与高分续答
- **追问 1**：如何处理长文档中的跨段落问题？
  - **续答**：对于跨段落问题，我们采用父文档检索：先召回子片段，再返回其所在的父文档段落作为上下文。同时，在切分时保留相邻片段的链接，生成时拼接前后片段。样本是200个跨段落问题，口径是答案完整率，从60%提升到82%。
:::

::: details 🛠️ 换成你自己的项目时改这三处
1. 将产品手册场景替换为法律合同审阅，切分时需保留条款编号和定义引用。
2. 引入基于嵌入的语义切分，使用text-embedding模型计算句子相似度，动态确定切分点。
3. 增加多语言场景，针对中英文混合文档设计不同的切分规则。
:::

### 题 3：腾讯混元大模型长程评测如何设计指标以反映真实业务效果？

> 🏢 **真题来源**：腾讯 · 混元大模型应用 / 评测产品面经

::: info 🎯 核心考点与破题关键
- **考点实质**：考察对长程对话评测体系的设计能力，包括多轮一致性、任务完成度、用户满意度等维度。
:::

::: tip 💡 参考回答示范
> “在混元大模型客服场景中，我负责设计长程评测方案。我们定义了一次会话为5轮以上对话，评测指标包括：任务完成率（用户问题是否解决）、多轮一致性（前后回答是否矛盾）、用户满意度（人工标注1-5分）。样本是1000个真实会话，口径是任务完成率，由标注员根据对话日志判断。我们设计了自动化指标：用规则检测矛盾（如价格前后不一致），用模型评估回答相关性。同时，引入用户反馈信号（如点赞、转人工）作为辅助。通过分析发现，任务完成率与对话轮次负相关，超过8轮后完成率下降20%。于是我们优化了上下文管理，引入摘要记忆，使完成率提升12%。”
:::

::: warning ⚠️ 连环追问与高分续答
- **追问 1**：如何保证评测的客观性？
  - **续答**：我们采用双盲标注，每个会话由两名标注员独立评分，计算Kappa系数确保一致性大于0.7。对于自动化指标，定期与人工标注做校准，确保偏差在5%以内。样本是200个会话的校准集，口径是评分一致性。
:::

::: details 🛠️ 换成你自己的项目时改这三处
1. 将客服场景替换为教育辅导长程对话，增加知识点覆盖度和学习效果指标。
2. 设计基于用户行为的隐式反馈指标，如会话时长、重复提问率。
3. 引入对抗测试，模拟用户故意刁难，评估模型鲁棒性。
:::

### 题 4：百度文心一言Token成本算账：如何优化提示词与缓存策略降低推理成本？

> 🏢 **真题来源**：百度 · 文心一言企业版 / 成本优化产品面经

::: info 🎯 核心考点与破题关键
- **考点实质**：考察对大模型推理成本结构的理解，包括输入输出token计费、缓存复用、提示词压缩等。
:::

::: tip 💡 参考回答示范
> “在文心一言企业版项目中，我负责降低API调用成本。我们分析发现，输入token占比70%，输出token占比30%。优化措施：1）提示词压缩：去除冗余指令，用缩写和结构化格式，平均减少20%输入token；2）缓存策略：对高频查询（如产品价格）缓存结果，设置TTL为1小时，命中率35%，节省15%成本；3）输出控制：设置max_tokens和停止符，避免模型过度生成。样本是过去三个月的调用日志，口径是每千次调用的平均成本。优化后，成本从每千次12元降至8元，降幅33%。我们同时监控了答案质量，确保准确率下降不超过2个百分点。”
:::

::: warning ⚠️ 连环追问与高分续答
- **追问 1**：如何平衡缓存与答案实时性？
  - **续答**：我们根据业务类型设置不同TTL：静态知识（如公司介绍）TTL为24小时，动态信息（如库存）TTL为5分钟。同时，缓存键包含用户上下文版本号，当知识库更新时自动失效。样本是缓存命中后的用户满意度，口径是满意度分数，与未缓存时无显著差异。
:::

::: details 🛠️ 换成你自己的项目时改这三处
1. 将企业版场景替换为内部知识问答，增加对敏感信息的脱敏处理成本。
2. 引入基于语义的缓存，用向量相似度匹配，提高命中率但增加检索开销。
3. 设计成本分摊模型，按部门统计token消耗，推动用量优化。

:::

::: tip 💡 参考回答示范
> “在可灵视频生成项目中，我负责优化首帧延迟。用户上传图片后，生成视频首帧的延迟直接影响放弃率。我们分析数据发现，延迟超过3秒时，放弃率从10%飙升至40%。优化措施：1）预生成：对常见模板提前生成首帧，缓存命中率20%；2）模型轻量化：使用蒸馏小模型生成首帧，延迟从2.5秒降至1.2秒，但画质略有下降，我们通过后处理增强；3）渐进式加载：先展示低清首帧，再逐步替换高清。样本是10万次生成请求，口径是放弃率（用户未等待完成即关闭页面的比例）。优化后，平均首帧延迟从2.8秒降至1.5秒，放弃率从25%降至12%。同时，我们监控了用户对画质的投诉率，确保不增加。”
:::

::: warning ⚠️ 连环追问与高分续答
- **追问 1**：如何平衡首帧速度与视频质量？
  - **续答**：我们采用分级策略：免费用户优先速度，首帧用轻量模型；付费用户优先质量，首帧用大模型但提供进度条。样本是不同用户群的留存率，口径是次周留存，付费用户留存提升5%。
:::

::: details 🛠️ 换成你自己的项目时改这三处
1. 将视频生成场景替换为3D模型生成，优化首屏渲染时间。
2. 引入边缘计算，将首帧生成下沉到CDN节点，减少网络延迟。
3. 设计用户预期管理，在等待时展示生成进度和预览效果。
:::
