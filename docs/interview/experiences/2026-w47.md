### 题 1：字节跳动飞书智能助手：如何设计多轮对话中的上下文管理策略以平衡效果与成本？

> 🏢 **真题来源**：字节跳动 · 飞书智能助手 / 企业协同AI产品面经

::: info 🎯 核心考点与破题关键
- **考点实质**：在长对话场景下，通过上下文窗口管理、摘要压缩与检索增强的混合策略，在保证回答准确性的同时控制token消耗与延迟。
:::

::: tip 💡 参考回答示范
> “我会从三个层面来设计。首先，明确业务目标：飞书智能助手需要处理会议纪要、文档问答、日程安排等多轮任务，平均对话轮次在5-10轮，但个别复杂任务可能超过20轮。样本是过去一个月内真实用户会话日志，口径是单次会话内用户与助手的交互轮次。我们发现超过8轮后，用户满意度下降15%，主要原因是助手忘记早期关键信息。因此，上下文管理是核心。
> 
> 第一，分层上下文策略：将上下文分为短期记忆（最近3轮对话原文）、中期记忆（通过LLM摘要压缩的历史对话，每5轮生成一次摘要，保留关键实体和意图）、长期记忆（用户画像和偏好，存储在向量库中，按需检索）。短期记忆直接放入prompt，中期记忆以摘要形式附加，长期记忆通过RAG检索相关片段。这样在8轮对话中，平均token消耗降低40%，而任务完成率保持95%以上。
> 
> 第二，动态窗口调整：根据任务类型动态决定上下文长度。例如，文档问答任务需要更长的文档片段，而日程安排只需最近几轮对话。我们设置规则：当检测到用户意图为“总结”或“对比”时，自动扩展上下文窗口至最近10轮，并触发摘要更新；当意图为“确认”或“简单查询”时，仅使用最近3轮。
> 
> 第三，成本与效果监控：定义核心指标——任务完成率（通过人工标注抽样评估）、平均响应延迟、单次会话token成本。我们每周抽样1000条会话进行人工评估，确保摘要压缩不丢失关键信息。同时，设置token消耗阈值，当单次会话超过5000 tokens时，触发告警并分析原因。
> 
> 在风控方面，对于涉及敏感信息（如薪酬、合同）的对话，禁止使用摘要压缩，必须保留原文，并增加人工审核环节。此外，所有摘要生成过程需记录日志，便于追溯。
> 
> 最后，与算法团队协作，定期更新摘要模型和检索策略，通过A/B测试验证效果。例如，我们对比了两种摘要方法：抽取式与生成式，发现生成式摘要更连贯但偶尔遗漏细节，因此结合使用：抽取式保留关键句，生成式补充连贯性。”
:::

::: warning ⚠️ 连环追问与高分续答
- **追问 1**：如何评估摘要压缩的质量？有没有量化指标？
  - **续答**：我们采用两个量化指标：信息保留率和压缩比。信息保留率通过人工标注关键信息点（如人名、时间、任务）在摘要中的出现比例，抽样100条对话，要求保留率>90%。压缩比是摘要长度与原文长度的比值，目标在0.3-0.5之间。同时，监控下游任务完成率的变化，如果下降超过5%，则回滚摘要策略。
- **追问 2**：如果用户突然切换话题，上下文管理如何应对？
  - **续答**：我们通过意图识别模型检测话题切换。当连续两轮用户意图与历史意图相似度低于阈值（如0.3），则触发话题重置：清空短期记忆，但保留长期记忆（用户画像）。同时，将之前对话的摘要存入历史记录，供用户后续回溯。这样避免无关上下文干扰，也减少token浪费。
:::

::: details 🛠️ 换成你自己的项目时改这三处
1. 将飞书场景替换为钉钉或企业微信，调整上下文分层策略中的具体轮次阈值。
2. 如果产品是面向C端的聊天机器人，可简化长期记忆，侧重短期记忆和摘要压缩。
3. 根据实际业务数据调整token消耗阈值和抽样评估频率。
:::

### 题 2：阿里巴巴淘宝问问：RAG检索中如何设计切分策略以提升商品问答准确性？

> 🏢 **真题来源**：阿里巴巴 · 淘宝问问 / 电商RAG产品面经

::: info 🎯 核心考点与破题关键
- **考点实质**：针对电商商品详情、用户评价、售后政策等异构文本，设计合理的文档切分与元数据关联策略，平衡检索粒度与上下文完整性，提升问答准确率。
:::

::: tip 💡 参考回答示范
> “淘宝问问需要回答用户关于商品规格、材质、适用场景、售后等问题，信息来源包括商品标题、详情页、用户评价、问答社区等。样本是过去三个月内用户提问日志，口径是每个问题对应的商品ID和期望答案类型。我们发现，简单按固定长度切分会导致答案碎片化，例如用户问“这件衣服适合冬天穿吗？”需要结合详情页的材质和用户评价中的体验。因此，切分策略必须结合业务语义。
> 
> 第一，按信息类型分层切分：商品标题和属性（如品牌、型号）作为独立短文本，直接作为元数据；详情页按段落切分，每段不超过200字，并保留段落标题作为元数据；用户评价按单条评价切分，每条评价附带评分和购买时间；问答社区按问答对切分。这样，每个片段都有明确的类型和来源。
> 
> 第二，元数据关联：每个片段存储商品ID、片段类型、位置索引、时间戳。检索时，先通过商品ID过滤，再根据问题类型选择片段类型。例如，问材质时优先检索详情页段落，问实际体验时优先检索用户评价。
> 
> 第三，重叠切分与上下文扩展：对于详情页段落，采用滑动窗口切分，窗口大小200字，重叠50字，避免边界信息丢失。检索后，将相邻片段一并返回，提供更完整上下文。实验表明，重叠切分使答案准确率提升12%。
> 
> 第四，评估与迭代：定义准确率指标——人工评估1000个问题，答案完全正确或部分正确的比例。初始切分策略准确率为78%，经过调整（增加重叠、按类型过滤）后提升至86%。同时，监控检索召回率，确保相关片段不被遗漏。
> 
> 风控方面，对于涉及价格、促销等敏感信息，必须确保片段来源是官方详情页而非用户评价，并在答案中注明来源。此外，定期更新切分规则，适应商品页模板变化。”
:::

::: warning ⚠️ 连环追问与高分续答
- **追问 1**：如何确定切分长度和重叠大小？
  - **续答**：我们通过实验确定：切分长度在150-250字之间，重叠50字。使用评估集测试不同参数下的答案准确率和检索延迟。最终选择200字+50字重叠，因为它在准确率和延迟间取得平衡。同时，对于短文本（如标题）不切分，长文本（如详情页）按段落切分。
- **追问 2**：用户评价切分后，如何保证评价的时效性？
  - **续答**：在元数据中记录评价时间，检索时根据问题类型决定是否加权。例如，问“最近质量如何”时，优先检索最近3个月的评价；问“长期使用感受”时，可检索更早评价。我们还在答案中注明评价时间范围，避免误导。
:::

::: details 🛠️ 换成你自己的项目时改这三处
1. 将电商场景替换为文档知识库，调整切分策略为按标题层级切分。
2. 如果产品是客服机器人，可增加对话历史作为上下文，与RAG结合。
3. 根据实际数据调整重叠大小和评估指标权重。
:::

### 题 3：腾讯广告AIGC创意生成：如何设计长程评测体系确保生成内容质量与合规？

> 🏢 **真题来源**：腾讯 · 广告AIGC创意 / 大模型内容生成评测面经

::: info 🎯 核心考点与破题关键
- **考点实质**：针对广告文案、图片等生成内容，构建覆盖相关性、吸引力、合规性的多维度长程评测体系，结合自动指标与人工评估，确保规模化生产下的质量稳定。
:::

::: tip 💡 参考回答示范
> “广告AIGC创意生成需要保证内容既吸引人又符合广告法和品牌规范。样本是过去半年内生成的10万条广告文案和5万张图片，口径是每条内容对应的广告主行业、投放平台和人工审核结果。我们设计了三层评测体系。
> 
> 第一层，自动指标筛查：对于文案，计算困惑度、重复率、情感倾向、关键词覆盖率（与广告主提供的关键词对比）；对于图片，使用CLIP score计算图文相关性，使用美学评分模型评估视觉质量。设定阈值，如困惑度高于100或重复率超过30%则标记为低质。这一层能过滤掉60%的明显问题。
> 
> 第二层，规则引擎合规检查：基于广告法禁用语库（如“最”、“第一”）、品牌黑名单、敏感词库进行匹配。同时，对于图片，使用OCR检测文字违规，使用图像分类模型检测是否包含违禁物品。规则引擎覆盖了90%的硬性合规问题。
> 
> 第三层，人工评估与模型迭代：每周抽样1000条内容，由3名标注员从相关性（是否传达产品卖点）、吸引力（是否激发点击）、合规性（是否违反广告法）三个维度打分（1-5分）。计算平均分和低分率。对于低分样本，分析原因并反馈给生成模型进行微调。例如，我们发现生成文案常出现夸张表述，通过增加负样本训练，低分率从15%降至8%。
> 
> 长程监控：建立仪表盘，监控每日生成量、自动筛查通过率、人工评估平均分、投诉率。当投诉率上升时，触发根因分析。同时，定期更新规则库和评估模型，适应法规变化。
> 
> 风控方面，对于医疗、金融等特殊行业，所有生成内容必须经过人工审核才能投放。此外，保留所有生成日志和评估记录，便于审计。”
:::

::: warning ⚠️ 连环追问与高分续答
- **追问 1**：自动指标与人工评估的结果不一致时如何处理？
  - **续答**：我们定期计算自动指标与人工评分的相关性。如果相关性低（如低于0.5），则调整自动指标权重或引入新指标。例如，我们发现困惑度与人工评分的相关性仅0.3，而关键词覆盖率相关性0.6，因此降低困惑度权重，增加关键词覆盖率的权重。同时，对于自动指标高分但人工低分的样本，进行案例分析，优化指标定义。
- **追问 2**：如何评估生成内容的多样性？
  - **续答**：我们使用distinct-n指标计算文案的n-gram多样性，并使用图像嵌入的方差衡量图片多样性。设定多样性阈值，避免生成内容过于同质化。同时，在人工评估中加入多样性维度，让标注员判断内容是否千篇一律。
:::

::: details 🛠️ 换成你自己的项目时改这三处
1. 将广告场景替换为电商商品描述生成，调整合规规则库为电商禁用语。
2. 如果生成内容为视频脚本，增加时序连贯性评估指标。
3. 根据业务规模调整抽样比例和人工评估频率。
:::

### 题 4：百度文心一言企业版：如何精细核算Token成本并设计定价策略？

> 🏢 **真题来源**：百度 · 文心一言企业版 / 大模型商业化产品面经

::: info 🎯 核心考点与破题关键
- **考点实质**：基于企业客户的实际调用模式，拆解Token成本结构（训练、推理、存储），设计阶梯定价与成本控制机制，实现商业可持续。
:::

::: tip 💡 参考回答示范
> “企业版大模型的成本核算必须细化到每个调用场景。样本是过去一个季度内100家企业客户的调用日志，口径是每次API调用的输入输出Token数、模型版本、调用时间。我们首先拆解成本：推理成本占70%，训练成本占20%，存储与运维占10%。推理成本中，GPU资源是主要部分，按每秒处理的Token数折算。
> 
> 第一，建立成本模型：对于每个模型版本，测算单Token推理成本。例如，文心一言4.0版本，单Token推理成本约为0.0001元（基于GPU小时成本和吞吐量）。输入和输出Token成本不同，输出通常更贵，因为需要自回归生成。我们按输入输出分别计价。
> 
> 第二，定价策略：采用阶梯定价，每月调用量越大单价越低。基础版定价为0.002元/千Token，企业版0.0015元/千Token，并设置免费额度（如每月100万Token）。同时，针对高频场景（如客服机器人）推出包年套餐，降低客户决策成本。
> 
> 第三，成本控制机制：提供Token用量监控面板，客户可设置预算告警；对于长文本，推荐使用摘要或分段处理以节省Token；对于非实时任务，提供批量接口，价格更低。我们还通过模型蒸馏和量化降低推理成本，将部分场景迁移到小模型，成本降低50%。
> 
> 第四，盈利分析：确保毛利率在30%以上。我们定期review每个客户的Token消耗和收入，对于用量大但毛利低的客户，协商调整定价或优化调用方式。
> 
> 风控方面，防止恶意刷量：设置单账户QPS限制，异常调用触发验证。同时，对于敏感行业（如金融）的调用，记录日志并审计。”
:::

::: warning ⚠️ 连环追问与高分续答
- **追问 1**：如何预测客户未来的Token消耗以做容量规划？
  - **续答**：我们基于历史调用数据，使用时间序列模型（如ARIMA）预测未来3个月的Token消耗，准确率在85%左右。同时，与销售团队同步客户增长计划，手动调整预测。容量规划时，预留20%的buffer应对峰值。
- **追问 2**：如果客户要求大幅折扣，如何评估是否接受？
  - **续答**：我们计算客户的边际成本：新增调用量带来的增量成本主要是推理成本，固定成本已分摊。如果折扣后价格仍高于边际成本，且能提升整体资源利用率，则可接受。同时，考虑战略价值，如行业标杆客户可适当让利。
:::

::: details 🛠️ 换成你自己的项目时改这三处
1. 将百度文心一言替换为其他大模型，调整成本参数和定价。
2. 如果产品是SaaS模式，增加订阅制定价选项。
3. 根据实际GPU成本波动调整成本模型。
:::

### 题 5：美团智能客服：如何设计高危写操作（如退款、改地址）的风控流程？

> 🏢 **真题来源**：美团 · 智能客服 / 大模型Agent风控产品面经

::: info 🎯 核心考点与破题关键
- **考点实质**：在Agent自动处理用户请求时，针对退款、修改订单等高危写操作，设计多级确认、权限校验与事后审计机制，平衡效率与安全。
:::

::: tip 💡 参考回答示范
> “智能客服Agent需要处理用户发起的退款、修改配送地址、取消订单等写操作，这些操作一旦出错可能造成资损或用户体验下降。样本是过去一年内智能客服处理的写操作请求，口径是每个请求的操作类型、用户意图识别置信度、最终结果。我们设计了四层风控。
> 
> 第一层，意图识别与置信度阈值：使用NLU模型识别用户意图，当置信度低于0.9时，转人工处理。对于退款意图，还需识别退款原因和金额，若金额超过100元，强制人工复核。
> 
> 第二层，操作前确认：对于高危操作，Agent必须向用户明确复述操作内容（如“您要退款订单123，金额50元，确认吗？”），并等待用户肯定回复。同时，在对话界面提供“取消”按钮。
> 
> 第三层，权限与规则校验：Agent调用后端API前，检查用户身份和订单状态。例如，已发货订单不能直接退款，需走退货流程；修改地址仅在配送前允许。规则引擎实时校验，不通过则返回提示。
> 
> 第四层，事后审计与熔断：所有写操作记录日志，包括操作时间、用户ID、操作内容、Agent决策依据。每日抽样5%的日志进行人工审计。若发现错误率超过1%，触发熔断，暂停自动写操作，全面检查。
> 
> 此外，对于高频操作（如修改地址），我们设置频率限制，防止恶意刷单。同时，与风控团队共建黑名单库，识别异常用户。
> 
> 在指标上，我们监控自动操作成功率、错误率、人工转接率。目标是将错误率控制在0.5%以下，人工转接率低于20%。”
:::

::: warning ⚠️ 连环追问与高分续答

> “在通义千问企业知识库场景中，切分策略直接影响检索召回和生成质量。我会先分析文档类型：对于结构化的产品手册，按章节和段落切分，样本是 500 份手册，口径是每份文档长度在 10 页以上；对于非结构化的会议纪要，按对话轮次或话题切分。我的切分原则是：第一，保证每个 chunk 语义完整，通常控制在 200-500 字，重叠窗口设为 50 字，避免信息割裂。第二，为每个 chunk 添加元数据，如文档标题、章节、页码，便于检索时过滤。第三，对于表格和图片，单独提取并转换为文本描述，作为独立 chunk。评估时，我会用检索命中率（Top-3 包含正确答案的比例）和生成答案的忠实度（人工评估）作为指标。样本是 100 个典型问题，口径是覆盖不同文档类型。如果命中率低，我会调整 chunk 大小或增加重叠；如果生成答案不完整，我会检查 chunk 是否遗漏关键信息。”
:::

::: warning ⚠️ 连环追问与高分续答
- **追问 1**：如何确定最优的 chunk 大小？
  - **续答**：我会通过 A/B 测试，对比不同 chunk 大小（如 200 字、300 字、500 字）下的检索命中率和生成质量。样本是 200 个问题，口径是每个问题有标准答案。同时，考虑计算成本，chunk 越小，索引越多，检索延迟可能增加。通常我会选择在命中率达标的前提下，尽量大的 chunk 以减少索引数量。
- **追问 2**：对于长文档，如何避免切分导致上下文丢失？
  - **续答**：我会采用层次化切分：先按章节切分，再在章节内按段落切分，并为每个 chunk 保留父章节的摘要作为元数据。检索时，如果命中某个 chunk，可以将其父章节的摘要一并提供给生成模型，以补充上下文。此外，对于关键段落，可以设置较大的重叠窗口。
:::

### 题 14：阿里巴巴夸克搜索 RAG：长文档切分策略如何平衡检索精度与生成连贯性？

> 🏢 **真题来源**：阿里巴巴 · 夸克 AI 搜索 / RAG 产品面经

::: info 🎯 核心考点与破题关键
- **考点实质**：考察对 RAG 中文档切分粒度、重叠窗口、语义边界识别等对检索召回与生成质量影响的理解，本质是精度与连贯性的权衡。
:::

::: tip 💡 参考回答示范
> “在夸克搜索的 RAG 项目中，我负责长文档问答的切分策略设计。我们处理的是网页和 PDF 文档，平均长度 5000 字。切分策略经历了三个阶段：初期按固定 512 token 切分，重叠 64 token，但发现检索精度尚可，生成答案经常断章取义，因为切分点落在句子中间。后来改为按段落和标题切分，保证每个 chunk 是完整语义单元，但 chunk 大小不均，有的长达 2000 token，导致检索时细粒度问题召回不准。最终我们采用「语义边界识别 + 动态窗口」：先用 NLP 模型识别句子边界和段落主题，优先在段落间切分，若段落过长（超过 800 token）再按句子边界切分，并设置 10% 重叠。同时为每个 chunk 生成摘要向量用于粗召回，再用原文向量精排。指标上，我们监控检索命中率（样本是 1000 条人工标注问答对，口径是 top3 chunk 包含答案的比例）和生成答案的连贯性评分（人工 1-5 分）。严禁编造。风控方面，对于法律、医疗等高风险领域，切分后额外加一层规则校验，确保关键条款不被切断。”
:::

::: warning ⚠️ 连环追问与高分续答
- **追问 1**：如何确定重叠窗口的大小？有没有量化方法？
  - **续答**：我会做小规模 A/B 实验：固定其他条件，重叠比例从 0%、5%、10%、15% 分别测试，看检索命中率和生成连贯性的变化。一般 10% 左右性价比最高，因为再增加重叠会增大索引体积和检索延迟。样本是每个比例 200 条 query，口径是 top5 召回率与人工连贯性评分。
- **追问 2**：对于表格和图片混排的文档，切分策略需要怎样调整？
  - **续答**：表格和图片不能按文本切分。我会将表格转为结构化文本（如 markdown 表格）并单独作为一个 chunk，图片则用 OCR 提取文字后与上下文合并。同时为表格和图片 chunk 添加类型标签，检索时根据 query 类型加权。比如问「表格数据」时，提高表格 chunk 的权重。
:::

::: details 🛠️ 换成你自己的项目时改这三处
1. 如果换成腾讯文档智能问答，文档类型更偏向协作文档，切分可结合版本历史和评论上下文，但核心语义边界识别逻辑不变。
2. 如果项目是客服知识库 RAG，文档短且结构化，可简化为按 QA 对切分，无需复杂语义识别，但需处理多轮对话的上下文拼接。
3. 如果算力受限无法做摘要向量，可改用关键词提取加 BM25 粗召回，再向量精排，但需接受召回率下降 5-10 个百分点。

- **考点实质**：考察对生成式 AI 产品中延迟与用户体验关系的理解，以及通过产品交互、预期管理、异步通知等策略降低放弃率的能力。
:::

::: tip 💡 参考回答示范
> “在可灵视频生成项目中，我负责首帧延迟优化。当时首帧平均延迟 8 秒，用户放弃率高达 30%。我们分析发现，用户放弃主要发生在等待前 3 秒，因为没有任何反馈。产品策略分四层：1）即时反馈：用户点击生成后，立即展示进度条和预估时间（基于历史分位数），并播放轻量动画，让用户感知系统在工作；2）分阶段展示：首帧生成后先展示低分辨率预览，同时后台继续生成高清版，用户可提前看到效果；3）异步通知：若预估时间超过 10 秒，提示用户可离开页面，生成完成后通过 push 或站内信通知；4）队列优化：对免费用户采用排队机制，显示前面等待人数，并提供加速券（观看广告或分享）。指标上，我们监控放弃率（样本是近 7 天生成请求，口径是点击生成后 30 秒内离开页面的比例）、首帧延迟分位数（P50、P90）、用户满意度。严禁编造。风控方面，预览图需加明显水印，防止用户误存低清版。”
:::

::: warning ⚠️ 连环追问与高分续答
- **追问 1**：如何准确预估生成时间，避免给用户错误预期？
  - **续答**：我会用机器学习模型预测：特征包括视频长度、分辨率、当前队列长度、用户优先级。用历史数据训练，目标是最小化预估误差。上线后监控预估准确率（样本是 1000 次生成，口径是实际时间在预估±20% 内的比例），低于 80% 则重新训练。
- **追问 2**：对于付费用户，是否应该完全消除等待？
  - **续答**：不能完全消除，因为物理延迟存在。但可以为付费用户提供专属队列和更高优先级，将 P90 延迟从 15 秒降到 5 秒。同时提供「极速模式」——降低分辨率换取速度，让用户选择。关键是透明沟通，避免付费用户产生不切实际的预期。

::: tip 💡 参考回答示范

::: warning ⚠️ 连环追问与高分续答

::: tip 💡 参考回答示范
> “在混元大模型的长程对话评测中，我首先明确长程对话的挑战：上下文遗忘、指代消解、话题漂移、一致性维持。评测体系包含三个层面：自动指标、人工评估、对抗测试。自动指标方面，我采用基于 GPT-4 的评分器，对每轮回复从相关性、一致性、信息量三个维度打分（1-5 分），并计算对话级的一致性得分（比如用 NLI 模型判断前后是否矛盾）。数据构造上，我设计了 200 组多轮对话，每组 10-20 轮，覆盖任务型（如订机票）和闲聊型，并注入干扰轮次（如用户突然切换话题再切回）。人工评估则抽样 50 组，由标注员从流畅性、有用性、安全性打分，并与自动评分做相关性分析（Spearman 系数需大于 0.7）。对抗测试包括故意重复、矛盾指令、长距离指代（如“它”指代 10 轮前的实体）。指标上，我们关注长程一致性准确率（样本是 200 组，口径是人工判断无矛盾的比例）和指代消解准确率。最终，评测报告会指出模型在 15 轮后性能下降明显，建议优化位置编码或引入记忆机制。”
:::

::: warning ⚠️ 连环追问与高分续答
- **追问 1**：如何低成本自动化评估长程一致性？
  - **续答**：我采用基于规则和模型结合的方法：先用规则检测显式矛盾（如数字、日期不一致），再用小模型（如 1B 参数）做 NLI 判断。同时，构建一个矛盾对数据集，微调小模型，使其在测试集上 F1 达到 0.85，成本仅为 GPT-4 的 1/10。
- **追问 2**：长程对话中如何评估安全性？
  - **续答**：我们设计多轮诱导攻击样本，比如先聊正常话题，再逐步引导到敏感话题。评估模型是否在任一环节输出不安全内容。指标是安全违规率（样本是 100 组攻击对话，口径是至少一次违规的比例）。同时，人工复核违规样本，确保标注一致性。
:::

::: details 🛠️ 换成你自己的项目时改这三处
1. 将混元换成其他模型，调整评测集和评分标准。
2. 针对客服场景，增加任务完成率指标，检查多轮后是否达成用户目标。
3. 引入用户模拟器自动生成多轮对话，扩大评测规模。
:::

### 题 40：百度 · 文心一言 Token 成本优化与定价策略如何算账？

> 🏢 **真题来源**：百度 · 文心一言产品经理（商业化方向）

::: info 🎯 核心考点与破题关键
- **考点实质**：考察对 LLM 推理成本结构的理解，包括 Token 消耗估算、成本分摊、定价模型与毛利测算。
:::

::: tip 💡 参考回答示范
> “在文心一言的 Token 成本优化中，我首先拆解成本结构：推理成本主要来自 GPU 算力，按 Token 计费。我们需要估算不同场景下的平均 Token 消耗。比如，一个典型问答场景，输入 200 token，输出 100 token，那么单次请求 300 token。假设 GPU 集群每百万 token 成本为 10 元（根据实测，样本是 1000 次请求，口径是平均输出长度 100 token，输入 200 token，总 token 数 30 万，成本 3 元，即每百万 token 10 元）。那么单次成本 0.003 元。定价时，我们采用阶梯定价：基础版每千 token 0.01 元，毛利率约 70%。但需考虑免费额度、高峰折扣等。优化策略包括：1）压缩提示词，减少输入 token；2）输出长度控制，设置 max_tokens；3）缓存常见问题答案，降低重复计算。我们通过 A/B 测试发现，提示词优化可降低 20% 输入 token。另外，对于长文档场景，采用分段处理，避免一次性输入过长。最终，我们建立成本监控看板，实时跟踪每百万 token 成本，并设置预算告警。”
:::

::: warning ⚠️ 连环追问与高分续答
- **追问 1**：如何评估缓存策略的收益？
  - **续答**：我们统计缓存命中率，样本是 10 万次请求，口径是相同 query 在 1 小时内重复出现。命中率约 15%，每次命中节省 300 token，则总节省 450 万 token，按每百万 10 元计算，节省 45 元。同时，缓存更新策略采用 LRU，设置 TTL 为 1 小时。
- **追问 2**：如果竞争对手降价，如何调整定价？
  - **续答**：我会先分析自身成本结构，确保降价后仍有毛利。然后，通过差异化定价：对高频用户提供折扣，对长尾用户维持原价。同时，推出按效果付费的套餐，比如按任务完成率收费，转移部分风险。最终，定价需覆盖成本并保持竞争力。
:::

::: details 🛠️ 换成你自己的项目时改这三处
1. 将文心一言换成其他模型，调整成本参数和定价。
2. 针对企业客户，采用私有化部署，成本模型改为硬件折旧+运维。
3. 引入混合精度推理，降低单 token 成本。
:::

### 题 41：美团 · 智能客服高危写操作风控如何设计？

> 🏢 **真题来源**：美团 · 智能客服产品经理（风控方向）

::: info 🎯 核心考点与破题关键
- **考点实质**：考察对 AI 系统中高危操作（如退款、改地址）的风控设计，包括权限控制、二次确认、审计与兜底。
:::

::: tip 💡 参考回答示范
> “在美团智能客服场景中，高危写操作包括退款、修改订单地址、取消订单等。我的风控设计遵循“最小权限+多重校验+可追溯”原则。首先，Agent 只能调用预定义的工具，每个工具都有风险等级。对于高危操作，必须满足三个条件：1）用户身份验证（如通过订单号+手机号后四位）；2）操作意图明确（用户明确表达退款，且 LLM 置信度高于 0.9）；3）二次确认（Agent 复述操作内容，用户确认后执行）。其次，设置金额阈值：单笔退款超过 500 元需转人工审核。第三，所有高危操作记录审计日志，包括操作时间、用户 ID、Agent 决策依据、执行结果。第四，设计兜底机制：如果操作失败或用户反悔，提供撤销入口（如 5 分钟内可取消退款）。指标上，我们监控高危操作误触发率（样本是 1000 次高危请求，口径是人工判定为错误操作的比例）和用户投诉率。上线后，误触发率从 5% 降至 0.5%。”
:::

::: warning ⚠️ 连环追问与高分续答
- **追问 1**：如何防止用户恶意诱导 Agent 执行高危操作？
  - **续答**：我们引入对抗训练，在训练数据中加入恶意诱导样本，让模型学会拒绝。同时，部署规则引擎，检测异常模式（如短时间内多次请求退款）。对于可疑请求，强制转人工。此外，用户信用体系也可作为参考，低信用用户的高危操作需更严格验证。
- **追问 2**：如果二次确认被用户忽略，如何设计？
  - **续答**：二次确认必须显式交互，比如用户需点击“确认退款”按钮或回复“确认”。如果用户未确认，操作不执行。我们还会在确认页面突出风险提示，如“退款后无法恢复”。对于语音场景，要求用户说出“确认”二字。
:::

::: details 🛠️ 换成你自己的项目时改这三处
1. 将美团场景换成电商或金融，调整高危操作类型和阈值。
2. 引入多因素认证，如短信验证码，提高安全性。
3. 设计分级授权，不同客服等级可执行不同风险操作。
:::

### 题 42：小红书 · 多模态搜索中图文相关性如何评估与优化？

> 🏢 **真题来源**：小红书 · 多模态搜索产品经理

::: info 🎯 核心考点与破题关键
- **考点实质**：考察对多模态搜索（图文匹配）的评估指标和优化策略，包括数据标注、模型选型、badcase 分析。
:::

::: tip 💡 参考回答示范
> “在小红书多模态搜索中，用户常通过图片搜索相似笔记或通过文本搜索配图。图文相关性评估是关键。我首先定义相关性等级：完全相关（图片直接展示 query 主体）、部分相关（图片包含 query 元素但非主体）、不相关。评估数据上，我构建了 1000 个 query-图片对，由标注员打标，口径是三人投票取多数。指标采用 NDCG@10 和准确率。优化策略分两步：1）模型层面，采用 CLIP 类双塔模型做图文嵌入，但发现对细粒度属性（如颜色、款式）区分不足，于是引入属性识别模型，提取图片中的物体、颜色、场景标签，与 query 做规则匹配，加权融合。2）数据层面，挖掘 badcase，发现主要错误是“背景干扰”和“多物体混淆”。针对背景干扰，我们训练一个主体检测模型，裁剪主体区域再计算相似度；针对多物体，采用多标签分类，计算 query 与每个标签的匹配度，取最大值。上线后，NDCG@10 提升 8%。”
:::

::: warning ⚠️ 连环追问与高分续答
- **追问 1**：如何评估多模态搜索的端到端体验？
  - **续答**：除了相关性指标，我们还看用户点击率和停留时长。通过 A/B 测试，对比新旧模型的 CTR 和人均点击次数。同时，收集用户反馈（如“不相关”按钮），计算反馈率。综合评估后，确定优化方向。
- **追问 2**：标注成本高，如何降低？
  - **续答**：采用主动学习：先用小模型预标注，人工只审核低置信度样本。同时，利用用户行为数据（如点击、收藏）作为弱监督信号，构建训练集。这样标注成本降低 50%，且模型效果保持。
:::

::: details 🛠️ 换成你自己的项目时改这三处
1. 将小红书换成电商平台，调整相关性定义和指标。
2. 引入视频搜索，评估时序相关性。
3. 针对垂直领域（如时尚），引入领域知识图谱增强匹配。
:::
