## 📅 2026-08-24｜概念专场：白板 Agent 设计与核心技术选型

### 题 1：这个需求配不配做 Agent？

> 🏢 **真题来源**：大厂 AI PM 现场白板面试题（“你现在设计一个 Agent 吧，什么场景你自己定”）

::: info 🎯 核心考点与破题关键
- **考点实质**：不要一上来就画框图。先用“三问法则”证明场景需要动态决策，而不是把固定流程强行包装成 Agent。
- **解题框架**：流程是否穷举 $\rightarrow$ 下一步是否依赖不确定输出 $\rightarrow$ 输入是结构化表单还是非结构化。
:::

::: tip 💡 参考回答示范
> “我会先判断‘该不该做 Agent’，再谈怎么做。能写成固定流程图的，不上 Agent。
> 
> 在面试现场，我不会先画大模型框图，而是先问三件事：
> 1. 固定 Workflow 能不能把路径穷举完？
> 2. 下一步动作是不是必须看上一步结果、且事先无法穷举？
> 3. 输入是规则字段，还是包含情绪、多附件的非结构化自然语言？
> 
> 比如**报销审批通常不该上 Agent**：金额档位、发票验真、超期驳回都能写成代码规则，Agent 只会更慢、更贵、偶尔砍偏。而**客户投诉处理更适合 Agent**：用户一段话里夹着订单号、物流和质量诉求，还带有强烈情绪，查完订单与履约状态后，系统才知道下一步是补偿代金券、催派还是转人工——这才是真正的动态决策。
> 
> 指标上，我会抽检 50 条真实客诉工单，业务与产研一起打标（可穷举 / 需动态决策 / 必须人审）。如果动态决策占比不足 20%，就先不立项 Agent 项目。上线后高频可穷举路径走 Workflow，长尾动态分支才交给 Agent。”
:::

::: warning ⚠️ 连环追问与高分续答
- **追问 1**：业务方坚持要‘全面 Agent 化’，你用哪三个判据拒绝？
  - **续答**：① 步骤是否可预先穷举；② 单任务 Token 成本与延迟预算是否超标；③ 错误执行的业务代价是否可逆。三者只要有一条不满足，坚决用 Workflow。
- **追问 2**：输入非结构化但步骤完全可穷举，做不做 Agent？
  - **续答**：不做端到端 Agent。采用‘LLM 结构化抽取（抽槽） + 固定代码工作流’，既利用了大模型的语义理解，又守住了工程确定性。
:::

::: details 🛠️ 换成你自己的项目时改这三处
1. **场景**：把「客户投诉处理」替换为你真实的业务（如设备故障排查、法务初审）；
2. **抽检规模**：把「抽检 50 条工单」替换为你的实际样本集；
3. **分流比例**：明确指出你的场景中规则分流与 Agent 动态分流的占比。
:::

### 题 2：决策层和执行层怎么拆？

> 🏢 **真题来源**：大厂 AI PM 面试设计题

::: info 🎯 核心考点与破题关键
- **考点实质**：考察 Agent 的分层解耦能力。规划可以先从简，但决策路由与执行层必须具备清晰的成败可观测性。
:::

::: tip 💡 参考回答示范
> “规划可以先写死，决策和执行绝不能糊在一起。决策错了方向错，执行错了用户直接受损。
> 
> 以**合同审查 Agent** 为例：
> 1. **规划层（可先规则化）**：写死四步（抽关键条款 $\rightarrow$ 对齐内部红线 $\rightarrow$ 标风险 $\rightarrow$ 出审查意见）；
> 2. **决策层（核心枢纽）**：判断当前付款条款走标准合规模板，还是因表述模糊需检索历史争议案例库；
> 3. **执行层（强信号反馈）**：PDF 解析、条款比对、向量检索每一次工具调用必须有明确的 HTTP/业务 Success/Fail 回执。
> 
> 产品经理在初期盯三件事：决策有没有完整日志记录、工具返回值能不能被 Schema 校验、单步失败后是重试、降级还是转人工。指标并列看工具调用成功率与任务完成率，样本是 X、口径是 Y。迭代顺序永远是：先把执行层做成完全可观测，再把高频稳定决策固化成规则，模型只负责长尾那一段。”
:::

::: warning ⚠️ 连环追问与高分续答
- **追问 1**：规划层什么时候必须从模板升级为模型自主规划？
  - **续答**：当业务步骤的排列组合经常变化、长尾例外情况超过模板覆盖上限时，才开放由模型进行 ReAct 自主规划。
- **追问 2**：工具没有明确的成败信号，产品层面如何兜底？
  - **续答**：当失败处理。自动重试一次，仍无明确状态则强制中断并转人工，同时向工程提出接口治理需求。
:::

::: details 🛠️ 换成你自己的项目时改这三处
1. **场景**：将「合同审查」替换为你实际的 Agent 场景；
2. **四步规划**：替换为你业务真实的步骤定义；
3. **可观测指标**：明确你们目前的 Tool Trace 字段规范。
:::

### 题 3：上线前如何划权限、校验与人工接管？

> 🏢 **真题来源**：大厂 AI 产品上线风控题

::: info 🎯 核心考点与破题关键
- **考点实质**：写操作风控是上线生死线。默认只读、写操作必须带依据、卡住必须平滑转人。
:::

::: tip 💡 参考回答示范
> “上线前必须画清三条线：**默认只读、结论必有依据、卡住必须有人接**。写权限必须一个一个逐步开放。
> 
> 以**退款 Agent** 为例：
> - **权限隔离**：Agent 可以查订单、查物流、查退款政策，但‘发起退款’绝不默认全自动放开。小额自动、超额必须人工确认——阈值与财务现有人审档位对齐；
> - **结果校验**：生成的退款结论必须精确指引到政策第几条第几款，给不出依据一律不放行；
> - **人工接管**：用户连续表达不满、金额超限、或系统自评估置信度低时，立即触发接管卡片，带走已查信息和推理上下文，不让客服从零问起。
> 
> 护栏盯‘越权拦截次数’与‘无依据放行数’。无依据放行直接定性为 P0 级事故。”
:::

::: details 🛠️ 换成你自己的项目时改这三处
1. **写工具名**：替换为你系统里最具风险的写接口（如转账、删库、改价）；
2. **小额阈值**：说明你业务里小额自动放行的具体金额依据；
3. **接管上下文**：列出转人工卡片中必须包含的 4 个核心字段。
:::

### 题 4：判断 Agent 好不好，看哪些核心指标？

> 🏢 **真题来源**：Agent 质量评估通用考题

::: info 🎯 核心考点与破题关键
- **考点实质**：拒绝只看点赞率。必须将**任务完成率、工具调用成功率、人工接管率与失败 Trace** 组合成体检大盘。
:::

::: tip 💡 参考回答示范
> “四个数必须一起看：**任务完成率、工具调用成功率、人工接管率、失败 Trace**。前三个是体温计，Trace 是听诊器。
> 
> - **完成率低但工具成功率高**：多半不是接口坏了，而是 Context 信息不足或决策路由卡死；
> - **接管率高且完成率吻合**：说明安全兜底机制在良好运转，不属于系统故障；
> - **口径严格对齐**：‘完成’是指业务对象状态变更成功（如工单关闭），而不是模型单方面宣称‘我已为您处理完毕’。
> 
> 严禁把接管率当作唯一的北极星指标，否则会逼着系统在遇到不确定问题时胡乱猜测作答。”
:::

::: details 🛠️ 换成你自己的项目时改这三处
1. **终态定义**：明确指出你业务中的“完成”由哪个数据库字段判定；
2. **Trace 工具**：说明你们线上使用的 APM/日志追踪系统名称；
3. **事故复盘**：准备一次“模型说完成了但实际没办成”的典型 Case。
:::

### 题 5：Prompt 调优与工作流分别解决什么？

> 🏢 **真题来源**：语核科技 AI 产品经理面

::: info 🎯 核心考点与破题关键
- **考点实质**：Prompt 管单点表达与角色规范；工作流（Workflow）管时序编排、条件分支与权限重试。
:::

::: tip 💡 参考回答示范
> “**Prompt 管‘怎么说、什么角色、什么格式、何时拒答’；工作流管‘先做什么、分支判断、失败重试、权限校验与多工具串联’**。能用 if-else 解决的，绝对不要堆进超长系统提示词里。
> 
> 遇到格式不稳、语气跑偏、偶发废话，改 Prompt 最快最省；一旦涉及多步骤依赖、条件跳流、写接口鉴权，必须下沉到工作流。在 Prompt 里硬写长流程，一改全崩，且无法进行单节点灰度与回滚。”
:::

### 题 6：Memory 怎么分层？为什么会有不可变长期记忆？

> 🏢 **真题来源**：语核科技 AI PM 面试深挖题

::: tip 💡 参考回答示范
> “不能把‘凡是进了向量库的’都笼统称为记忆。记忆必须按生命周期和修改权限分层：
> 1. **短期记忆**：当前会话 Context Window，会话结束即销毁；
> 2. **工作记忆（Working Memory）**：本轮任务的中间状态（已提取订单号、待补齐槽位）；
> 3. **长期记忆（Long-term Memory）**：跨会话的稳定偏好与事实（常用地址、语言偏好）；
> 4. **不可变长期记忆**：企业组织红线、法务合规、品牌口径与核心制度——**只能通过后台发版更新，严禁被用户的单次对话诱导改写**。”
:::

### 题 7：内部知识库：选 RAG、微调还是纯 Prompt？

> 🏢 **真题来源**：面灵 2026 指南 / 语核科技

::: tip 💡 参考回答示范
> “**知识更新用 RAG，口吻风格用 Prompt，特定语法或小模型提效才用微调**。
> 内部知识库制度经常变动、要求精准原文溯源，必须选 RAG；微调无法解决事实实时更新，微调完制度变了，模型依然会背出旧条款产生严重幻觉。治理幻觉必须先按检索漏、上下文丢、模型编造三层归因，低置信度坚决拒答。”
:::

### 题 8：文档切片切大还是切小？

> 🏢 **真题来源**：牛客 AI PM 面经汇总

::: tip 💡 参考回答示范
> “切片粒度不能按固定的 512 字一刀切，必须按文档的语义结构定。太大噪声多且浪费 Context，太小会导致法条断裂丢掉前提条件。针对制度按‘条款’切，保留父级章节标题元数据；表格按行切并携带表头；利用父子切块（Parent-Child Chunking）做精准召回与完整上下文供给。”
:::

### 题 9：为什么向量检索要和 BM25 混合？

> 🏢 **真题来源**：牛客大模型检索专项

::: tip 💡 参考回答示范
> “向量检索擅长口语化表达和同义改写，但在精确匹配专有名词、产品型号、错误码（如 `E10086`）时极易翻车；BM25 关键词检索正好能精确命中术语和编号。两者混合召回（Hybrid Search）再配合 Reranker 重排序，在召回阶段保覆盖度，在精排阶段压制无关噪声。”
:::

### 题 10：Function Calling 与 MCP 有什么区别？

> 🏢 **真题来源**：牛客 / 语核 Tool Use 专项

::: tip 💡 参考回答示范
> “**Function Calling 是单个模型与工具之间的调用协议；MCP（Model Context Protocol）是跨模型、跨 Agent 的标准化连接架构**。单应用少工具直接用 FC；若工具需在多个智能体或异构模型间复用，引入 MCP 能够大幅降低重复开发胶水代码的成本，并实现统一权限与审计。”
:::

### 题 11：为什么搭了 Agent 不用 Workflow / Prompt+大模型？

### 题 13：Agent 使用弊端是什么，产品上怎么兜底？

> 🏢 **真题来源**：字节飞书一面

::: tip 💡 参考回答示范
> “我最防范 Agent 的四大弊端：**同输入结果不一致、出错无法单节点回放、长链调用成本延迟失控、ReAct 空转死循环**。
> 产品兜底上：限制最大规划步数（如 Max Step = 3）、所有写操作强制二次确认、同一行数据写入必须带幂等键、超出步数降级为草稿。”

### 题 14：用过飞书多维表格吗？用过哪些模块？

> 🏢 **真题来源**：飞书生态必考题

::: tip 💡 参考回答示范

> 4. **AI 字段**：做抽取与摘要，抽取结果默认进‘待确认视图’，人工确认后才触发下游自动化。”

### 题 19：回答质量不错但留存差，怎么定位？

### 题 39：RAG 分层评估：为什么不能只看最终回答对不对？
