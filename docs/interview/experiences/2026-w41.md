### 题 1：字节跳动飞书智能助手如何设计Agent工作流，平衡任务完成率与响应延迟？

> 🏢 **真题来源**：字节跳动 · 飞书 AI 助理 / 企业级 Agent 产品面经

::: info 🎯 核心考点与破题关键
- **考点实质**：核心是设计多步骤 Agent 编排，在有限延迟内完成跨应用操作，并量化完成率与延迟的权衡。
:::

::: tip 💡 参考回答示范
> “我在飞书智能助手项目中负责 Agent 工作流设计。首先明确任务边界：用户通过自然语言发起如“安排下周与产品团队的评审会并预定会议室”的请求，需要调用日历、会议室、人员目录等多个 API。我设计了基于意图识别的分层编排：第一层用轻量模型（如 7B 参数）做意图分类和槽位填充，第二层用大模型（如 70B 参数）做复杂规划和异常处理。样本是过去 3 个月飞书内 5000 条真实用户请求，口径是端到端任务完成率（用户无需二次干预即达成目标）和 P95 响应延迟。我们通过异步执行和预取策略，将平均延迟从 4.2 秒降到 2.8 秒，完成率从 68% 提升到 82%。具体措施：1）对高频操作（如查日程）走缓存和规则引擎，延迟 <500ms；2）对复杂操作（如跨时区协调）采用流式输出中间状态，让用户感知进度；3）设置超时降级，若大模型规划超过 3 秒则切换为模板化流程。风控上，涉及写操作（如创建会议）必须二次确认，并记录审计日志。”
:::

::: warning ⚠️ 连环追问与高分续答
- **追问 1**：如果用户请求涉及敏感权限（如访问高管日历），你如何设计降级和风控？
  - **续答**：我会在意图识别阶段加入权限校验层。样本是 200 条涉及高管日历的请求，口径是权限拒绝率与用户满意度。对于无权限请求，不直接报错，而是返回“需要审批”的引导，并自动发起审批流。同时，Agent 只读取脱敏后的空闲/忙碌状态，不暴露具体日程内容。若审批通过，则临时授予一次性 Token，操作完成后立即回收。风控上，所有敏感操作记录操作人、时间、目标，并同步到安全审计系统。
:::

::: details 🛠️ 换成你自己的项目时改这三处
1. 将飞书场景换成钉钉或企业微信，调整 API 调用方式和权限模型。
2. 将任务完成率指标改为“首次响应准确率”，因为有些任务需要多轮交互。
3. 如果公司没有自研大模型，可替换为调用外部 API，但需增加网络延迟和成本考量。
:::

### 题 2：阿里巴巴国际站 RAG 检索中，如何设计切分策略以提升长文档问答准确率？

> 🏢 **真题来源**：阿里巴巴 · 国际站 AI 客服 / RAG 产品面经

::: info 🎯 核心考点与破题关键
- **考点实质**：核心是文档切分粒度与检索召回、生成质量的权衡，需结合业务文档结构设计动态切分。
:::

::: tip 💡 参考回答示范
> “在国际站 AI 客服项目中，我们处理大量商品描述、物流政策、关税规则等长文档。样本是 1000 份平均长度 8000 词的商品文档，口径是问答准确率（人工评估答案是否包含正确信息且无幻觉）。最初用固定 512 token 切分，准确率只有 62%，因为切分点常打断关键条款。后来改为基于语义和结构的动态切分：1）先按标题、列表、表格等结构分割，保证每个块语义完整；2）对超长段落用滑动窗口重叠 20% 切分；3）对表格和图片说明单独处理，保留上下文。同时，在检索阶段加入元数据过滤（如商品类目、更新时间），召回 top-5 块后，用重排序模型（如 bge-reranker）精排。最终准确率提升到 79%，P95 检索延迟从 800ms 降到 500ms。成本上，切分块数增加 30%，但通过缓存和向量索引优化，整体 Token 消耗仅增加 10%。”
:::

::: warning ⚠️ 连环追问与高分续答
- **追问 1**：如果文档更新频繁，如何保证检索索引的实时性？
  - **续答**：我们采用增量索引策略。样本是每天更新 200 份文档，口径是索引延迟和查询一致性。对于新增或修改的文档，触发实时向量化并更新索引，延迟控制在 1 分钟内。对于删除的文档，先标记为失效，查询时过滤。同时，设置版本号，确保用户查询时看到的是最新版本。如果更新量突增，则降级为批量更新，并通知用户可能看到旧数据。
:::

::: details 🛠️ 换成你自己的项目时改这三处
1. 将国际站文档换成法律合同或医疗指南，切分策略需更注重条款完整性。
2. 如果使用开源向量数据库，需考虑其增量更新性能，可能需换成 Pinecone 或 Weaviate。
3. 将准确率指标改为“答案可溯源率”，因为客服场景要求提供出处。
:::

### 题 3：腾讯混元大模型长程评测：如何设计多轮对话的自动化评估方案？

> 🏢 **真题来源**：腾讯 · 混元大模型 / 对话系统产品面经

::: info 🎯 核心考点与破题关键
- **考点实质**：核心是构建覆盖多轮上下文一致性、任务完成度的自动化评测框架，减少人工评估成本。
:::

::: tip 💡 参考回答示范
> “在混元大模型对话产品中，我们需要评估模型在多轮对话中的表现。样本是 500 组人工构造的多轮对话，每组 5-10 轮，口径是任务完成率（最后一轮是否达成用户目标）和上下文一致性（是否出现矛盾）。我们设计了自动化评估流水线：1）用规则引擎检查关键槽位是否在轮次间保持一致；2）用另一个大模型（如 GPT-4）作为裁判，对每轮回复打分（1-5 分），并给出理由；3）对任务完成率，定义明确的成功条件（如预订酒店需包含日期、房型、确认号），由脚本自动验证。为了校准裁判模型，我们人工标注了 100 组对话作为金标准，裁判模型与人工评分相关性达到 0.85。最终，自动化评估将评测周期从 2 周缩短到 2 天，成本降低 70%。但注意，裁判模型本身有偏差，我们定期用人工抽查修正。”
:::

::: warning ⚠️ 连环追问与高分续答
- **追问 1**：如何评估模型在长对话中的“遗忘”问题？
  - **续答**：我们设计“记忆探测”轮次：在对话进行到第 8 轮时，突然询问第 2 轮提到的信息。样本是 200 组对话，口径是记忆准确率。如果模型回答错误，则标记为遗忘。同时，我们计算上下文窗口利用率，若对话长度接近模型上限，则提示可能遗忘。改进措施包括：在关键信息出现时，让模型生成摘要并重复，或使用外部记忆库。
:::

::: details 🛠️ 换成你自己的项目时改这三处
1. 将混元换成其他大模型，需调整裁判模型的 prompt 和评分标准。
2. 如果业务场景是客服，任务完成率定义需更严格，如必须解决用户问题。
3. 将自动化评估改为半自动，人工只复核低分对话，以平衡成本与准确率。
:::

### 题 4：蚂蚁集团信贷场景：如何计算大模型 Token 成本并设计降本方案？

> 🏢 **真题来源**：蚂蚁集团 · 信贷 AI 助手 / 大模型成本优化面经

::: info 🎯 核心考点与破题关键
- **考点实质**：核心是拆解 Token 消耗结构，通过缓存、压缩、模型选型等手段在保证效果下降低成本。
:::

::: tip 💡 参考回答示范
> “在蚂蚁信贷 AI 助手中，我们每天处理 10 万次用户咨询。样本是过去一个月 300 万次调用，口径是单次咨询平均 Token 消耗和总成本。最初使用 70B 模型，平均每次消耗 1500 Token（输入+输出），成本约 0.03 元/次，月成本 90 万元。我们做了以下优化：1）意图分类和简单问答（如“利率是多少”）用 7B 模型或规则引擎，覆盖 40% 请求，成本降至 0.002 元/次；2）对复杂问题，用 70B 模型，但通过 prompt 压缩（去除冗余示例）和输出限制（max_tokens=200），将 Token 消耗降到 1000；3）引入缓存，对高频问题（如“如何还款”）缓存答案，命中率 25%，节省 20% 成本。最终月成本降至 45 万元，效果指标（回答准确率）仅下降 1.5%。风控上，所有涉及金额、利率的回答必须从知识库检索，禁止模型自由生成。”
:::

::: warning ⚠️ 连环追问与高分续答
- **追问 1**：如果用户问题需要多轮推理，缓存失效，如何进一步降本？
  - **续答**：对于多轮推理，我们采用“思维链压缩”：让模型在中间步骤生成简洁的推理摘要，而非完整思考过程。样本是 1000 组多轮对话，口径是推理准确率和 Token 消耗。压缩后 Token 减少 30%，准确率不变。另外，我们使用投机解码（speculative decoding）加速推理，降低单位时间成本。如果仍超预算，则对非关键场景降级为 7B 模型，并提示用户“正在使用快速模式”。
:::

::: details 🛠️ 换成你自己的项目时改这三处
1. 将信贷场景换成电商客服，高频问题不同，缓存策略需调整。
2. 如果公司自研模型，可调整模型架构降低推理成本，但需重新训练。
3. 将成本指标改为“每解决一个用户问题的成本”，更贴近业务价值。
:::

### 题 5：美团高危写操作风控：AI 助手如何安全执行退款、改地址等操作？

> 🏢 **真题来源**：美团 · 客服 AI 助手 / 写操作风控产品面经

::: info 🎯 核心考点与破题关键
- **考点实质**：核心是设计写操作的多级确认与回滚机制，在提升效率的同时防止误操作和欺诈。
:::

::: tip 💡 参考回答示范
> “在美团客服 AI 助手中，用户可能要求“退款到银行卡”或“修改配送地址”。样本是过去半年 5 万次写操作请求，口径是误操作率（用户投诉因 AI 操作导致损失）和欺诈率。我们设计了三层风控：1）意图识别后，判断是否为高危操作（如退款金额>100 元、修改地址跨城市），若是则触发二次确认，要求用户输入验证码或点击确认按钮；2）操作前，调用风控系统检查用户历史行为、设备指纹，若风险分高则转人工；3）操作后，记录详细日志，并支持 5 分钟内一键回滚（如退款撤销、地址改回）。同时，AI 只执行有明确规则的操作，如退款金额必须与订单一致，否则拒绝。最终，误操作率从 0.5% 降到 0.1%，欺诈率未上升。但转人工率增加了 15%，我们通过优化确认话术（如“请确认退款金额 50 元到尾号 1234 的银行卡”）将用户放弃率控制在 5% 以内。”
:::

::: warning ⚠️ 连环追问与高分续答
- **追问 1**：如果用户坚持要求执行高风险操作，但风控系统拦截，如何安抚？
  - **续答**：我们设计安抚话术：先共情（“理解您着急”），再解释风控原因（“为了您的资金安全”），最后提供替代方案（“您可以联系人工客服快速处理”）。样本是 500 次拦截，口径是用户满意度。同时，记录拦截原因，若某类拦截频繁且合理，则优化规则。对于高价值用户，可提供绿色通道，但需人工复核。
:::

::: details 🛠️ 换成你自己的项目时改这三处
1. 将美团场景换成银行或支付，风控要求更严，需符合金融监管。
2. 如果写操作涉及第三方系统，需增加 API 幂等性和重试机制。
3. 将误操作率指标改为“操作成功率”，因为有些操作失败是用户主动取消。
:::

### 题 6：小红书多模态搜索：如何设计图文混合检索的评测指标？

> 🏢 **真题来源**：小红书 · 多模态搜索 / AI 产品面经

::: info 🎯 核心考点与破题关键
- **考点实质**：核心是定义多模态检索的相关性、多样性和时效性指标，并构建自动化评测集。
:::

::: tip 💡 参考回答示范
> “在小红书多模态搜索中，用户可能上传图片找相似笔记，或输入文字找相关图片。样本是 2000 条真实搜索 query（含图片和文字），口径是 top-10 结果的点击率和人工相关性评分。我们设计了三个指标：1）相关性：用 CLIP 模型计算 query 与结果的向量相似度，并人工标注 500 条作为校准，要求 top-3 相关性≥4 分（5 分制）；2）多样性：计算 top-10 结果的类目分布熵，避免全是同一类笔记；3）时效性：对时尚、美妆等类目，要求 30 天内笔记占比≥60%。自动化评测流水线：先用模型打分，再对低分结果人工复核。上线后，点击率提升 12%，用户搜索满意度（NPS）提升 8 分。挑战在于多模态对齐，我们通过对比学习微调 CLIP 模型，使图文匹配准确率从 75% 提升到 88%。”
:::

::: warning ⚠️ 连环追问与高分续答
- **追问 1**：如果用户上传的图片质量差或模糊，如何保证检索效果？
  - **续答**：我们加入图像增强预处理：先检测模糊度，若低于阈值则提示用户“图片模糊，是否重新上传”，同时用超分辨率模型增强。样本是 300 张模糊图片，口径是检索成功率。增强后，成功率从 40% 提升到 65%。另外，对于模糊图片，检索时降低图像权重，更多依赖文字描述。
:::

::: details 🛠️ 换成你自己的项目时改这三处
1. 将小红书换成淘宝或京东，商品图片检索需更注重属性匹配。
2. 如果多模态模型自研，需考虑训练成本和数据标注。
3. 将点击率指标改为“加购率”或“收藏率”，更贴近电商场景。
:::

### 题 7：字节跳动飞书智能助手：如何设计Agent工作流编排以处理多轮会议纪要生成与待办提取？

> 🏢 **真题来源**：字节跳动 · 飞书 AI / 企业协同 Agent 产品面经

::: info 🎯 核心考点与破题关键
- **考点实质**：考察对Agent工作流编排的理解，包括任务分解、工具调用、状态管理以及与企业IM场景的结合。
:::

::: tip 💡 参考回答示范
> “我以飞书会议纪要场景为例。首先，我会将任务拆解为：语音转写→摘要生成→待办提取→责任人匹配→日历创建。Agent需要调用飞书开放接口，如获取会议录音、查询参会人日历、创建待办。工作流引擎采用状态机，每个节点有输入输出schema。关键点：1）异步处理长音频，设置超时和重试；2）摘要生成使用大模型，但需限制token消耗，我会设置分段摘要再合并；3）待办提取需结构化输出，用function call格式。指标上，样本是1000场会议，口径是端到端完成率>95%，待办提取准确率>90%。风控方面，涉及写操作如创建日历，必须二次确认，避免误操作。”
:::

::: warning ⚠️ 连环追问与高分续答
- **追问 1**：如果会议中多人同时说话，转写准确率下降，如何优化？
  - **续答**：我会引入声纹分离和说话人日志，先做语音分离再转写。同时，在摘要阶段，用大模型结合上下文推断发言人意图。样本是200场重叠语音会议，口径是转写准确率从70%提升到85%。如果仍不达标，降级为人工校对入口。
- **追问 2**：如何评估待办提取的准确性？
  - **续答**：定义准确率=正确提取的待办数/总待办数，召回率=正确提取/实际待办。人工标注500场会议作为golden set，要求准确率>90%，召回>85%。同时监控用户对生成待办的编辑率，编辑率<10%为健康。
:::

::: details 🛠️ 换成你自己的项目时改这三处
1. 将飞书会议纪要换成钉钉闪记，需适配钉钉的API和权限体系。
2. 将待办提取换成工单创建，需对接Jira或内部工单系统。
3. 将会议场景换成客服对话质检，Agent需实时分析并触发预警。
:::

### 题 8：阿里巴巴国际站：RAG检索增强生成中，如何设计多语言商品知识库的切分与检索策略？

> 🏢 **真题来源**：阿里巴巴 · 国际站 AI 搜索 / RAG 产品面经

::: info 🎯 核心考点与破题关键

### 题 13：字节跳动 · 飞书智能伙伴：如何设计企业知识库Agent的检索与切分策略，平衡准确率与响应延迟？

> 🏢 **真题来源**：字节跳动 · 飞书 AI 产品面经

::: info 🎯 核心考点与破题关键
- **考点实质**：考察RAG系统中文档切分、索引构建、检索召回与重排的工程权衡，以及对企业场景下实时性要求的理解。
:::

::: tip 💡 参考回答示范
> “我在飞书智能伙伴项目中负责知识库问答的检索链路设计。当时遇到的核心矛盾是：企业文档格式复杂（PDF、PPT、表格、聊天记录），切分粒度太粗会导致召回不精准，太细又增加检索次数和延迟。我的方案是采用动态分层切分：对于结构化文档（如制度文件），按标题层级切分为段落，每个段落保留父级标题作为上下文；对于非结构化聊天记录，按对话轮次切分，并合并同一主题的连续消息。索引阶段，我们用了混合检索：稀疏向量（BM25）保证关键词匹配，稠密向量（如bge-m3）保证语义匹配，然后通过RRF融合排序。为了控制延迟，我们设置了召回上限：稀疏和稠密各召回Top 50，融合后取Top 20进入重排模型（如bge-reranker），最终取Top 5给大模型生成。实测下来，在内部1万份文档的测试集上，准确率从纯稠密的72%提升到混合检索的89%，P99延迟控制在800ms以内。关键决策点：切分时保留元数据（如文档标题、部门、更新时间），检索时支持元数据过滤，比如只搜“人力资源部”最近半年的文档。另外，我们做了缓存层，对高频问题缓存检索结果，命中率约30%，进一步降低延迟。”
:::

::: warning ⚠️ 连环追问与高分续答
- **追问 1**：如果企业文档每天新增上千份，如何保证索引实时更新且不影响线上查询？
  - **续答**：我们采用了增量索引+双缓冲机制。新文档先写入临时索引，每5分钟合并到主索引，合并时使用别名切换，线上查询无感知。同时，对于紧急更新的文档，提供手动触发重建的入口，但会限制频率。另外，我们监控索引延迟指标，如果超过10分钟，就告警并降级为只搜旧索引，保证可用性。
- **追问 2**：如何评估检索环节的准确率？有没有量化指标？
  - **续答**：我们构建了包含500个问题的评测集，每个问题标注了正确答案所在的文档片段。指标包括：Recall@5（前5个结果中包含正确答案的比例）、MRR（平均倒数排名）、以及端到端的答案准确率（人工评估）。上线前Recall@5为85%，上线后通过bad case分析持续优化切分策略，两个月后提升到92%。
:::

2. 如果换成微信客服场景，需处理短文本和口语化表达，切分策略改为按消息会话窗口滑动。
3. 如果延迟要求更严（如200ms），可去掉重排模型，仅用混合检索+规则过滤。

::: warning ⚠️ 连环追问与高分续答
- **追问 1**：如何降低人工评估的成本？有没有办法用自动化替代大部分人工？
  - **续答**：我们尝试了两种自动化方法：1）基于规则的关键信息抽取，比如用NER提取对话中的实体，然后检查后续是否出现；2）用LLM生成问题来测试记忆，比如让LLM根据历史生成“用户之前提到的航班号是什么？”然后看模型回答。但自动化在一致性判断上仍有局限，比如隐喻或隐含矛盾。目前我们采用自动化预筛选，把疑似错误的对话挑出来给人工复核，这样人工工作量减少了60%。
- **追问 2**：如果模型在长程对话中表现不佳，产品侧可以有哪些补救措施？
  - **续答**：产品侧可以：1）提供对话摘要功能，让用户随时查看之前聊过的要点；2）设计记忆锚点，允许用户固定重要信息，模型在后续回答中优先参考；3）限制单次对话轮数，超过一定轮数后建议开启新会话，并自动迁移关键信息；4）在关键决策点（如支付）要求用户二次确认，避免因记忆错误导致损失。
:::

::: details 🛠️ 换成你自己的项目时改这三处
1. 如果换成百度文心一言，需考虑搜索增强场景，评测中增加对实时信息的记忆。
2. 如果换成Kimi，需侧重长文档阅读后的多轮问答，评测文档内容记忆。
3. 如果换成DeepSeek，可关注代码生成场景的多轮调试一致性。

### 题 16：美团 · 外卖智能客服：如何计算大模型Token成本并设计降本方案，在保证体验的前提下优化ROI？

> 🏢 **真题来源**：美团 · 外卖 AI 产品面经

::: info 🎯 核心考点与破题关键
- **考点实质**：考察对大模型API成本结构的理解，以及通过缓存、模型选型、prompt优化等手段降低Token消耗的产品设计能力。
:::

::: tip 💡 参考回答示范
> “我在美团外卖智能客服项目中负责成本优化。当时每天有百万级对话，使用GPT-3.5-turbo，每月Token成本约30万元。我的目标是降低50%成本且不降体验。首先，我拆解了成本构成：输入Token占70%，输出Token占30%。输入中，系统prompt和用户历史占大头。优化措施：1）精简系统prompt，从500字压缩到200字，去掉冗余示例，成本降15%；2）对用户历史进行摘要，只保留最近3轮和关键信息，而不是全部历史，成本降20%；3）引入缓存层，对高频问题（如“配送费多少”）的答案缓存，命中率25%，成本降10%；4）模型分级：简单问题（如查询订单状态）用更便宜的模型（如通义千问-turbo），复杂问题用GPT-3.5，成本降10%。综合下来，成本降低55%，而满意度（CSAT）仅下降1个百分点（从92%到91%）。关键决策：我们设定了成本红线，如果某个月成本超预算，就临时提高缓存命中率或降级模型，但会监控CSAT，低于90%就回滚。”
:::

::: warning ⚠️ 连环追问与高分续答
- **追问 1**：如何准确预测每个对话的Token消耗？有没有办法在对话开始前就估算？
  - **续答**：我们训练了一个轻量级模型，根据用户第一句话和意图分类，预测对话轮数和每轮Token数。准确率约85%，用于动态分配预算。比如预测消耗高的对话，就提前启用更激进的摘要策略。另外，我们实时监控每个对话的Token消耗，超过阈值就告警并截断。
- **追问 2**：如果业务要求必须使用最新的大模型（如GPT-4），成本会翻倍，如何说服业务方接受降级方案？
  - **续答**：我会用数据说话：先做A/B测试，对比GPT-4和GPT-3.5在核心指标（如解决率、满意度）上的差异。如果差异小于2%，就建议用GPT-3.5，并展示成本节省。如果差异大，则建议混合方案：简单问题用便宜模型，复杂问题用GPT-4，这样成本增加可控，且关键体验不降。同时，我会推动模型侧优化，比如用蒸馏技术把小模型效果提上来。
:::

::: details 🛠️ 换成你自己的项目时改这三处
1. 如果换成滴滴客服，需考虑行程安全场景，对准确性要求极高，可能不能降级模型。
2. 如果换成小红书社区客服，需处理大量图片和文本，Token计算需包含多模态成本。
3. 如果换成蚂蚁金服，需考虑金融合规，所有对话必须留痕，缓存策略需谨慎。
:::

### 题 17：快手 · 可灵AI：如何设计视频生成中的高危写操作风控机制，防止滥用与内容违规？

> 🏢 **真题来源**：快手 · 可灵 AI 产品面经

::: info 🎯 核心考点与破题关键
- **考点实质**：考察对AIGC内容安全、用户权限、操作审计与实时拦截的产品设计，平衡创作自由与风险控制。
:::

::: tip 💡 参考回答示范
> “在可灵AI视频生成项目中，我负责设计高危写操作的风控机制。高危操作包括：生成涉及政治敏感、暴力、色情的内容，以及批量生成、盗用他人素材等。我们的风控体系分三层：1）事前预防：用户上传素材时，用图像识别模型检测违规内容，拦截并提示；同时，对生成prompt进行文本审核，敏感词直接拒绝。2）事中拦截：生成过程中，实时抽样关键帧进行内容审核，如果发现违规，立即终止生成并标记用户。3）事后审计：所有生成记录留存6个月，支持回溯。对于高危用户（如多次违规），限制其生成权限或封号。为了平衡体验，我们设定了分级策略：普通用户每天限生成10个视频，VIP用户50个，企业用户可定制。另外，我们引入了“信用分”体系，初始100分，违规扣分，低于60分则限制功能。实测中，风控系统拦截了99.5%的违规内容，误杀率（正常内容被误判）控制在2%以内。关键点：我们用了多模型投票机制，三个审核模型同时判断，只要两个认为违规就拦截，降低误判。”
:::

::: warning ⚠️ 连环追问与高分续答
- **追问 1**：如果用户用谐音或隐喻绕过文本审核，如何应对？
  - **续答**：我们采用了动态更新的敏感词库和语义模型。语义模型能理解上下文，比如“那个地方”结合历史可能指向敏感地点。同时，我们鼓励用户举报，举报后人工复核，并将新变种加入词库。另外，对于视频内容，我们更依赖图像和音频审核，因为文本绕过容易，但画面难以伪装。
- **追问 2**：如何评估风控系统的效果？有哪些指标？
  - **续答**：核心指标：违规内容拦截率（召回率）、误杀率（精确率）、用户投诉率、人工复核量。我们每周统计，并做bad case分析。拦截率目标>99%，误杀率<1%。如果误杀率上升，就调整阈值或增加人工复核。同时，我们监控用户生成量，如果因为风控导致正常用户流失，就需优化策略。
:::

::: details 🛠️ 换成你自己的项目时改这三处

2. 如果换成抖音，需考虑直播场景的实时风控，延迟要求更高。
3. 如果换成微信视频号，需结合社交关系链，对多次违规者限制分享。

### 题 18：小红书 · 多模态搜索：如何设计图文笔记的跨模态检索方案，提升搜索相关性？

> 🏢 **真题来源**：小红书 · 多模态 AI 产品面经

::: info 🎯 核心考点与破题关键
- **考点实质**：考察多模态检索中的向量化、跨模态对齐、索引构建与相关性评估，以及对社区内容特点的理解。
:::

::: tip 💡 参考回答示范
> “在小红书多模态搜索项目中，我负责设计图文笔记的跨模态检索。用户可以用文字搜图片，也可以用图片搜文字。核心挑战是：图文笔记的文本和图像语义需要对齐。我们的方案：1）对每篇笔记，用多模态模型（如CLIP）分别提取文本向量和图像向量，然后拼接或融合成一个联合向量，存入向量数据库。2）查询时，如果用户输入文字，就提取文本向量，与联合向量计算相似度；如果输入图片，就提取图像向量。3）为了提升相关性，我们加入了质量分和时效性因子：质量分基于点赞收藏评论，时效性基于发布时间，最终得分 = 相似度 * 质量分 * 时效衰减。实测中，跨模态搜索的点击率比纯文本搜索提升20%，但我们也发现，CLIP对细粒度语义（如“红色连衣裙”vs“粉色连衣裙”）区分不够，所以我们在精排阶段引入了细粒度分类模型，对Top 100结果重新打分。另外，我们构建了评测集，包含500个查询，人工标注相关笔记，计算NDCG@10，上线后从0.45提升到0.62。”
:::

::: warning ⚠️ 连环追问与高分续答
- **追问 1**：如何解决多模态向量索引的存储和检索性能问题？
  - **续答**：我们用了FAISS索引，并做了量化压缩（PQ），将向量从768维压缩到128维，存储降低80%，检索速度提升3倍，精度损失约2%。同时，我们分片存储，按笔记类别（如美妆、穿搭）分片，查询时只搜相关分片，减少计算量。对于热门查询，我们缓存结果，命中率30%。
- **追问 2**：如果用户上传的图片包含文字，如何利用？
  - **续答**：我们用了OCR提取图片中的文字，作为额外特征加入文本向量。比如用户上传一张带有“OOTD”字样的图片，OCR识别后，文本向量会包含这个词，提升检索相关性。同时，我们也会把OCR文本作为笔记的补充描述，用于文本搜索。
:::

::: details 🛠️ 换成你自己的项目时改这三处
1. 如果换成淘宝搜索，需考虑商品属性结构化，多模态检索要结合类目预测。
2. 如果换成微信搜一搜，需考虑公众号文章和聊天记录的混合检索，隐私要求高。
3. 如果换成抖音搜索，需考虑视频帧序列，多模态检索要处理时序信息。
:::
