## 📅 2026-09-21｜名企高价值真题同步与深度推演

### 题 1：字节跳动飞书智能助手多轮任务编排中状态丢失如何解决？

> 🏢 **真题来源**：字节跳动 · 飞书智能伙伴 / 企业 Agent 产品面经

::: info 🎯 核心考点与破题关键
- **考点实质**：Agent 工作流编排中上下文管理与状态持久化的产品设计，核心是解决长链路任务中的用户意图漂移与系统记忆断裂。
:::

::: tip 💡 参考回答示范
> “我在飞书智能伙伴项目里负责过会议纪要自动生成并派发待办的 Agent 工作流。当时遇到的核心问题是：用户先让助手总结会议纪要，再要求把其中三条行动项分别指派给不同负责人并设置截止时间，最后追问其中一位负责人的历史任务。助手在第三轮时丢失了前两轮的实体信息，导致指派错人。我们的样本是 500 个真实企业会话日志，口径是任务完成率（以最终待办成功创建且责任人正确为准），优化前完成率只有 62%。我的解法分三步：第一，在编排层引入显式状态槽位，把会议 ID、行动项列表、负责人映射、截止时间存为结构化 JSON，每轮对话后更新，而不是依赖大模型隐式记忆。第二，用规则引擎做实体对齐，当用户说‘他’时，回溯最近一轮提到的负责人，如果歧义则主动反问确认。第三，设计状态快照与回滚，如果用户中途修改某个行动项，只回滚该分支，不影响其他已确认项。上线后任务完成率提升到 89%，平均对话轮次从 4.2 降到 3.1。风控上，对于指派待办这类写操作，必须让用户二次确认卡片，确认后才调用飞书开放接口。”
:::

::: warning ⚠️ 连环追问与高分续答
- **追问 1**：如果用户在多轮中频繁切换任务，比如从会议纪要跳到查日程再跳回来，状态槽位怎么管理？
  - **续答**：我会引入任务栈和注意力权重。每个任务有独立的状态容器，用户切换时把当前任务压栈，新任务开新栈。当用户说‘回到刚才的会议’时，根据最近活跃时间和语义相似度恢复对应栈。同时给每个槽位打上时间戳和置信度，超过 3 轮未提及且置信度低于 0.6 的槽位自动过期，避免旧状态污染新任务。在飞书场景里，我们还会结合用户当前打开的文档或聊天窗口做上下文注入，比如用户正在看某篇会议纪要，就默认把该纪要 ID 作为当前任务根实体。
:::

::: details 🛠️ 换成你自己的项目时改这三处
1. 把飞书会议纪要换成钉钉智能填表或企业微信审批流，状态槽位改为表单字段和审批节点映射。
2. 把任务完成率指标换成审批一次通过率或待办按时完成率，口径相应调整。
3. 如果没有开放平台接口，可以改为模拟写操作，用数据库事务保证状态一致性，并加入人工审核兜底。
:::

### 题 2：阿里巴巴国际站 RAG 检索中商品标题切分粒度如何影响召回？

> 🏢 **真题来源**：阿里巴巴 · 国际站 AI 导购 / 电商 RAG 产品面经

::: info 🎯 核心考点与破题关键
- **考点实质**：RAG 中文档切分策略对检索召回率与生成准确率的权衡，核心是商品标题、属性、描述的多粒度索引设计。
:::

::: tip 💡 参考回答示范
> “我在国际站 AI 导购项目里负责商品知识库的 RAG 链路。当时商品数据包含标题、类目、属性键值对、详情描述和买家评论。最初我们把整个商品详情页按 512 token 切块，结果用户搜‘防水蓝牙音箱 户外’时，召回的商品很多是室内音箱，因为‘防水’和‘户外’被切到了不同块里。我们的样本是 2000 条真实搜索 query 和人工标注的相关商品，口径是 Top10 召回中相关商品占比，优化前只有 54%。我做了三件事：第一，标题和属性单独建索引，标题按词粒度切分，属性按键值对切分，保证‘防水等级 IPX7’这种强信号不被稀释。第二，详情描述按语义段落切分，用滑动窗口重叠 20%，避免边界信息丢失。第三，检索时做多路召回融合，标题路权重 0.5，属性路 0.3，描述路 0.2，再用 cross-encoder 重排。上线后 Top10 相关商品占比提升到 78%，生成答案的幻觉率从 18% 降到 7%。成本上，多路召回使检索耗时从 80ms 增加到 150ms，但通过缓存热门 query 的向量和倒排结果，P99 控制在 200ms 以内。”
:::

::: warning ⚠️ 连环追问与高分续答
- **追问 1**：如果商品标题很短，比如只有 5 个字，切分后信息量不足怎么办？
  - **续答**：对于短标题，我不会强行切分，而是把标题、类目路径、核心属性拼成一个增强文本块，比如‘防水蓝牙音箱 > 户外音箱 > IPX7 防水 > 20W 输出’。同时利用同义词扩展，把‘防水’扩展为‘IPX7、IPX8、防泼溅’等，写入索引。在召回阶段，对短标题 query 提高类目路径的权重，因为短 query 往往意图宽泛，类目能帮助收敛。我们还会用商品点击日志训练一个 query-标题相关性模型，对短标题做加权，确保它们不会被长描述淹没。
:::

::: details 🛠️ 换成你自己的项目时改这三处
1. 把国际站商品换成小红书笔记或抖音商品，切分策略改为笔记标题、标签、正文段落。
2. 把召回率指标换成点击率或加购率，用 A/B 实验验证切分策略对业务指标的影响。
3. 如果没有 cross-encoder 重排资源，可以用 BM25 和向量检索的加权融合，权重通过网格搜索确定。
:::

### 题 3：腾讯混元大模型长程评测中如何设计多轮一致性指标？

> 🏢 **真题来源**：腾讯 · 混元大模型 / 对话式 AI 评测产品面经

::: info 🎯 核心考点与破题关键
- **考点实质**：大模型长程对话评测体系设计，核心是量化多轮对话中的角色一致性、事实一致性和指令遵循衰减。
:::

::: tip 💡 参考回答示范
> “我在混元大模型对话评测项目里负责多轮一致性评测集的设计。当时业务方反馈模型在 10 轮以后经常忘记初始设定，比如一开始说‘你是一个严谨的医生’，到第 8 轮就变成推荐偏方。我们的样本是 300 组人工构造的多轮对话，每组 15 轮，口径是第 10 轮之后角色保持正确的对话占比，基线模型只有 61%。我设计了三个指标：第一，角色一致性，用规则加小模型判断回复是否符合初始角色设定，比如医生角色不能推荐未经证实的疗法。第二，事实一致性，抽取对话中提到的实体和属性，检查后续轮次是否矛盾，比如第 2 轮说‘患者 35 岁’，第 12 轮不能变成‘28 岁’。第三，指令遵循衰减率，统计每轮中明确指令（如‘用表格回答’）的遵守比例，画出随轮次变化的曲线。评测时采用双人标注加仲裁，Kappa 系数 0.82。根据评测结果，我们建议在训练时加入长程一致性损失，并在推理时用系统提示词每 5 轮重申角色。优化后角色一致性提升到 84%，事实一致性从 72% 提升到 91%。”
:::

::: warning ⚠️ 连环追问与高分续答
- **追问 1**：如果模型在长对话中主动询问用户以澄清信息，这算一致性好吗？
  - **续答**：主动澄清是好的，但要看是否偏离角色。比如医生角色在信息不足时问‘请问患者有无药物过敏史’是符合角色的，应该加分。但如果问‘你刚才说的年龄是多少’而用户之前已经说过，这就是记忆失败，要扣分。我在评测里会区分‘合理澄清’和‘记忆丢失’，前者要求问题与当前任务相关且未在之前轮次问过，后者则与历史信息矛盾。具体实现上，我会用对话状态跟踪模块检查模型提问是否已存在于历史槽位中，如果存在则标记为记忆问题。
:::

::: details 🛠️ 换成你自己的项目时改这三处
1. 把混元换成 Kimi 或 DeepSeek 的长文本对话，评测集改为 20 轮以上的文档问答，指标增加引用准确性。
2. 把角色一致性换成工具调用一致性，检查多轮中是否重复调用相同工具或遗漏必要参数。
3. 如果没有小模型辅助判断，可以用规则模板加关键词匹配，但需要人工抽检 10% 校准。
:::

### 题 4：美团智能客服 Token 成本暴涨如何做精细化算账与压缩？

> 🏢 **真题来源**：美团 · 智能客服 / 大模型应用产品面经

::: info 🎯 核心考点与破题关键
- **考点实质**：大模型应用成本控制，核心是 Token 消耗归因、缓存策略、模型分级和提示词压缩。
:::

::: tip 💡 参考回答示范
> “我在美团智能客服项目里负责成本优化。当时每天 200 万次对话，平均每次消耗 1800 token，其中系统提示词占 600，历史对话占 800，用户当前 query 和检索结果占 400。按每百万 token 10 元算，一天成本 3.6 万元，一个月超过 100 万。我们的口径是单次对话平均 token 消耗和问题解决率，优化前解决率 68%。我做了四件事：第一，系统提示词从 600 压缩到 220，去掉冗余示例，用结构化指令代替自然语言描述。第二，历史对话只保留最近 3 轮和关键实体摘要，摘要由小模型生成，每轮节省约 500 token。第三，对高频问题（如退款进度、配送时间）建立缓存，缓存命中率 35%，命中后直接返回模板加变量，不调用大模型。第四，模型分级，简单意图用 7B 模型，复杂投诉用 70B 模型，分级准确率 92%。优化后单次对话平均 token 降到 950，成本下降 47%，问题解决率反而提升到 73%，因为响应更快、答案更聚焦。风控上，缓存答案每 24 小时更新一次，避免政策变化导致错误。”
:::

::: warning ⚠️ 连环追问与高分续答
- **追问 1**：缓存命中率只有 35%，如何提升？会不会导致答案过时？
  - **续答**：提升缓存命中率的关键是 query 归一化。我们把用户 query 先过一层意图识别和槽位填充，比如‘我的外卖怎么还没到’和‘订单怎么还没送来’归一化为‘配送延迟查询’，这样缓存键从原始文本变成意图加槽位。归一化后命中率能到 55%。过时问题用 TTL 加版本号解决：每个缓存条目有有效期，默认 1 小时，政策类问题 15 分钟，并且当后台政策更新时主动失效相关缓存。另外，缓存只用于事实型问答，对于需要推理或个性化的问题不走缓存。
:::

::: details 🛠️ 换成你自己的项目时改这三处
1. 把美团客服换成滴滴客服或电商客服，高频问题换成行程异常、退换货政策。
2. 把 token 成本换成 GPU 推理成本，模型分级改为不同规格的实例，算账口径改为每千次对话的 GPU 小时。
3. 如果没有小模型做摘要，可以用规则抽取实体和动作，牺牲一点流畅度换取成本下降。
:::

### 题 5：蚂蚁集团高危写操作风控中如何设计 AI 确认与熔断机制？

> 🏢 **真题来源**：蚂蚁集团 · 智能金融助手 / 高危操作风控产品面经

::: info 🎯 核心考点与破题关键
- **考点实质**：AI Agent 执行资金、权限等写操作时的风控体系，核心是意图确认、额度限制、熔断和审计。
:::

::: tip 💡 参考回答示范
> “我在蚂蚁智能金融助手里负责转账和理财赎回的 AI 写操作风控。当时用户可以通过对话发起转账，比如‘给张三转 5000 块’。风险在于：大模型可能误解金额或收款人，或者被恶意 prompt 注入绕过确认。我们的样本是 1000 笔模拟转账请求，口径是风险拦截率和误拦率，目标是拦截率 100%，误拦率低于 2%。我设计了四层风控：第一层，意图解析后生成确认卡片，明确展示收款人、金额、账户，用户必须点击确认，不能用语音或文字‘好的’代替。第二层，额度分级，单笔超过 5000 元或当日累计超过 2 万元，触发人工客服复核。第三层，熔断机制，如果同一用户 1 分钟内发起 3 次以上转账，或检测到 prompt 注入特征（如‘忽略之前指令’），直接冻结会话并转人工。第四层，全链路审计，每个操作记录原始 query、解析结果、确认记录和最终执行结果，保存 5 年。上线后模拟测试拦截率 100%，误拦率 1.3%，主要误拦来自用户口音导致的金额识别错误，通过二次语音确认解决。”
:::

::: warning ⚠️ 连环追问与高分续答
- **追问 1**：如果用户是视障人士，无法点击确认卡片，怎么兼顾无障碍和风控？
  - **续答**：我们会提供语音确认通道，但要求用户读出随机验证码加金额，比如‘确认转账 5000 元，验证码 3847’。系统用声纹识别确认是本人，同时 ASR 转写验证码和金额，两者匹配才执行。对于视障用户，还会默认降低单笔限额到 2000 元，并强制人工客服回拨确认大额转账。这样既满足无障碍要求，又不降低风控标准。我们内部测试过 50 位视障用户，成功率和风控拦截率都达标。
:::

::: details 🛠️ 换成你自己的项目时改这三处
1. 把转账换成修改密码或删除数据，确认方式改为二次密码加短信验证码。
2. 把蚂蚁金融换成企业 SaaS 的权限变更，熔断机制改为异常时间或异常 IP 触发。
3. 如果没有人工客服复核资源，可以用规则引擎加延迟执行，比如大额操作延迟 5 分钟执行，期间可撤销。
:::

### 题 6：小红书多模态笔记理解中图文不一致如何影响推荐？

> 🏢 **真题来源**：小红书 · 多模态内容理解 / 推荐 AI 产品面经

::: info 🎯 核心考点与破题关键
- **考点实质**：多模态大模型在图文笔记理解中的一致性检测与标签生成，核心是解决封面图与正文语义冲突导致的推荐偏差。
:::

::: tip 💡 参考回答示范
> “我在小红书多模态内容理解项目里负责笔记标签生成。当时发现很多笔记封面图是美食，但正文在讲减肥餐，或者封面是风景，正文是穿搭。推荐系统如果只依赖封面图标签，会把笔记推给错误人群，导致点击率低。我们的样本是 5000 篇人工标注的图文笔记，口径是标签与正文主题一致率，优化前只有 67%。我做了三件事：第一，用多模态模型分别提取图像标签和文本标签，然后做一致性校验，如果图像标签和文本标签的余弦相似度低于 0.5，则标记为不一致，以文本标签为主，因为用户搜索和阅读更多依赖文本。第二，对于不一致笔记，生成一个融合标签，比如‘美食封面+减肥餐正文’生成‘减肥食谱’标签，并降低封面图的权重。第三，在推荐排序中引入一致性特征，不一致笔记的初始曝光降低 20%，但保留探索流量，如果互动率高再提权。上线后标签一致率提升到 89%，相关笔记点击率提升 12%，用户负反馈下降 8%。成本上，多模态推理每天增加 300 元 GPU 成本，但通过只对头部 20% 笔记做多模态，长尾用轻量模型，整体可控。”
:::

::: warning ⚠️ 连环追问与高分续答
- **追问 1**：如果图文不一致是用户故意为之，比如封面用夸张图片吸引点击，怎么处理？
  - **续答**：这种情况要区分恶意标题党和创意表达。我们会看正文是否与封面有合理解释，比如封面是夸张的‘吃草’，正文是‘一周减脂餐’，这算创意，不惩罚。但如果封面是豪车，正文是普通穿搭，且用户举报多，就判定为标题党，降低推荐权重并减少曝光。具体用举报率和完播率做判断：举报率高于 5% 或完播率低于 20% 的不一致笔记，进入人工审核池。同时，我们会给用户一个‘封面与内容不符’的反馈按钮，积累数据训练分类器。
:::

::: details 🛠️ 换成你自己的项目时改这三处
1. 把小红书换成抖音或快手短视频，多模态改为视频帧、音频和字幕的一致性检测。
2. 把标签一致率换成推荐点击率和转化率，用在线 A/B 实验验证。
3. 如果没有多模态大模型，可以用 CLIP 做图像文本相似度，再结合规则判断。
:::
