### 题 1：字节跳动 · 飞书智能助手Agent工作流编排中如何设计写操作审批与回滚机制？

> 🏢 **真题来源**：字节跳动 · 飞书 AI / 企业协同Agent产品面经

::: info 🎯 核心考点与破题关键
- **考点实质**：企业级Agent涉及写操作（如创建日程、发送消息、修改文档）时，产品需平衡自动化效率与操作风险，设计审批链与回滚策略。
:::

::: tip 💡 参考回答示范
> “我在设计飞书智能助手Agent时，首先明确写操作的风险等级：低风险如创建个人待办，中风险如向群组发送消息，高风险如修改共享文档权限或删除日程。对于中高风险操作，我设计了两级审批机制：第一级是Agent在执行前向用户发起确认卡片，展示操作摘要和影响范围；第二级是对于涉及多人协作的操作，自动触发审批流，由相关权限人确认。回滚机制上，我们为每个写操作生成操作快照，并保留7天可回滚窗口。指标上，样本是内部500人试点团队，口径是每周写操作请求量约2000次，其中高风险操作占比8%，审批通过率92%，回滚率0.5%。我们严禁编造数据，所有指标均来自试点监控看板。”
:::

::: warning ⚠️ 连环追问与高分续答
- **追问 1**：如果审批人长时间不响应，Agent如何避免流程阻塞？
  - **续答**：我们设置了超时策略：审批请求发出后，若30分钟内未响应，Agent会降级为只读建议模式，并将操作暂存到待办列表，同时通过飞书消息提醒审批人。对于紧急操作，用户可手动触发二次提醒或转交审批。
:::

::: details 🛠️ 换成你自己的项目时改这三处
1. 将飞书场景替换为钉钉或企业微信，调整审批流对接的API和权限模型。
2. 根据自身项目，定义不同的风险等级和审批阈值，例如金额超过1000元的操作需财务审批。
3. 回滚窗口可根据业务需求调整为1天或30天，并设计对应的存储成本核算。
:::

### 题 2：阿里巴巴 · 电商RAG检索中如何设计切分策略以平衡召回精度与延迟？

> 🏢 **真题来源**：阿里巴巴 · 电商知识库RAG产品面经

::: info 🎯 核心考点与破题关键
- **考点实质**：RAG系统中文档切分粒度直接影响检索召回质量与响应延迟，需结合电商商品描述、用户评价等非结构化数据特点设计动态切分方案。
:::

::: tip 💡 参考回答示范
> “在电商RAG场景，我们处理的是商品详情、用户问答和售后政策等文档。切分策略上，我采用语义与结构混合切分：首先按文档结构（标题、段落）粗切，再基于句子嵌入相似度进行细切，确保每个块在256-512 token之间。对于商品参数表，我们按行切分并保留表头上下文。为了平衡精度与延迟，我们引入两级检索：第一级用BM25快速召回Top 50块，第二级用向量检索重排Top 10。指标上，样本是10万条商品文档，口径是平均响应延迟从800ms降至350ms，召回率@10从78%提升至89%。所有数据来自A/B测试，严禁编造。”
:::

::: warning ⚠️ 连环追问与高分续答
- **追问 1**：如何处理长文档（如售后政策）的跨块语义依赖？
  - **续答**：我们为长文档建立块间链接，检索时若命中某块，会同时拉取相邻块作为上下文。同时，在块元数据中记录文档ID和位置，生成答案时按顺序拼接。
:::

::: details 🛠️ 换成你自己的项目时改这三处
1. 根据自身业务文档类型（如法律合同、医疗记录），调整切分粒度和重叠比例。
2. 引入基于LLM的语义切分替代规则切分，但需评估成本与延迟。
3. 设计检索缓存机制，对高频查询结果缓存，进一步降低延迟。
:::

### 题 3：腾讯 · 混元大模型长程对话评测体系如何设计以避免指标失真？

> 🏢 **真题来源**：腾讯 · 混元AI对话产品面经

::: info 🎯 核心考点与破题关键
- **考点实质**：长程对话（多轮、跨天）的评测需兼顾一致性、记忆保持和任务完成率，传统单轮指标易失真，需设计分层评测框架。
:::

::: tip 💡 参考回答示范
> “我们设计了三层评测体系：第一层是单轮质量（相关性、流畅性），用人工标注的1-5分评估；第二层是多轮一致性，通过构造对话历史，检查模型是否自相矛盾或遗忘关键信息，采用脚本化测试用例；第三层是任务完成率，针对具体场景（如订票、客服）定义成功标准。指标上，样本是500组多轮对话（平均10轮），口径是人工评估一致性得分4.2/5，任务完成率76%。我们严禁编造，所有数据来自内部评测平台。为避免指标失真，我们定期更新测试集，并引入对抗样本。”
:::

::: warning ⚠️ 连环追问与高分续答
- **追问 1**：如何量化“记忆保持”这一主观指标？
  - **续答**：我们设计记忆探测问题：在对话第N轮插入关键信息（如用户姓名），在第N+5轮提问该信息，统计正确回忆率。同时，用LLM自动评估回答是否包含该信息，人工抽检10%校准。
:::

::: details 🛠️ 换成你自己的项目时改这三处
1. 根据自身产品对话轮次特点，调整测试集轮次分布（如短对话3轮，长对话20轮）。
2. 引入用户真实日志构建评测集，但需脱敏处理。
3. 将评测指标与业务KPI（如客服解决率）关联，验证评测有效性。
:::

### 题 4：百度 · 文心一言Token成本算账：如何设计按场景分级的计价与配额策略？

> 🏢 **真题来源**：百度 · 文心一言商业化产品面经

::: info 🎯 核心考点与破题关键
- **考点实质**：大模型API的Token成本随输入输出长度波动，产品需设计精细化的计价模型和配额管理，平衡用户体验与毛利。
:::

::: tip 💡 参考回答示范
> “我们首先对用户场景分级：轻量问答（<500 token）、文档分析（500-4000 token）、长文生成（>4000 token）。针对不同级别，设计阶梯计价：轻量问答按次计费（如0.01元/次），文档分析按输入Token计费（如0.001元/千token），长文生成按输出Token计费（如0.002元/千token）。同时，为免费用户设置每日配额（如10次轻量问答），付费用户按套餐提供额度。指标上，样本是1万活跃用户，口径是平均每用户月消耗Token 5万，毛利率维持在45%。我们通过监控看板实时跟踪成本，严禁编造数据。”
:::

::: warning ⚠️ 连环追问与高分续答
- **追问 1**：如何防止用户恶意刷量导致成本激增？
  - **续答**：我们实施速率限制（如每分钟10次请求）和异常检测（如短时间内相同query重复请求），触发后要求验证码或降级服务。同时，对免费配额设置硬上限，超出后需付费。
:::

::: details 🛠️ 换成你自己的项目时改这三处
1. 根据自身模型成本结构（如训练成本分摊、推理成本），调整计价单元。
2. 设计企业级套餐，包含固定Token包和超额按量计费。
3. 引入缓存机制，对常见问题答案缓存，减少重复计算成本。
:::

### 题 5：美团 · 到店业务Agent高危写操作（如修改订单）的风控设计

> 🏢 **真题来源**：美团 · 到店Agent产品面经

::: info 🎯 核心考点与破题关键
- **考点实质**：Agent在到店场景中可能执行修改订单、退款等高危操作，需结合业务规则和实时风控，避免资损和用户体验受损。
:::

::: tip 💡 参考回答示范
> “我们为Agent设计了三道风控防线：第一道是意图确认，Agent在执行前必须复述用户意图并获取明确确认（如“您要取消订单123，确认吗？”）；第二道是规则引擎校验，检查操作是否违反业务规则（如已消费订单不可退款）；第三道是实时风控，接入美团风控系统，对异常操作（如高频退款）进行拦截。对于高风险操作，我们要求人工客服介入。指标上，样本是试点期间5000次Agent操作，口径是高危操作拦截率100%，误拦截率2%，用户满意度4.5/5。所有数据来自风控日志，严禁编造。”
:::

::: warning ⚠️ 连环追问与高分续答
- **追问 1**：如何平衡风控严格性与操作效率？
  - **续答**：我们根据用户信用分和操作历史动态调整风控强度：高信用用户简化确认步骤，新用户或异常行为触发加强验证。同时，提供“一键转人工”通道，减少用户等待。
:::

::: details 🛠️ 换成你自己的项目时改这三处
1. 根据自身业务的高危操作定义（如金融交易、医疗建议），调整风控规则。
2. 接入第三方风控服务或自建规则引擎，需评估响应延迟。
3. 设计用户教育环节，提前告知Agent能力边界，降低误操作预期。
:::

### 题 6：小红书 · 多模态笔记理解中如何设计图文匹配与标签生成评测？

> 🏢 **真题来源**：小红书 · 多模态内容理解产品面经

::: info 🎯 核心考点与破题关键
- **考点实质**：多模态模型需准确理解笔记中的图像与文本关联，并生成精准标签，评测需覆盖图文一致性、标签覆盖率和业务相关性。
:::

::: tip 💡 参考回答示范
> “我们构建了多模态评测集，包含1万篇笔记（图文对），人工标注了图文匹配度（1-5分）和黄金标签集。评测指标包括：图文匹配准确率（模型判断匹配与人工一致的比例）、标签召回率（生成标签覆盖黄金标签的比例）和标签精确率（生成标签中正确的比例）。指标上，样本是1万篇笔记，口径是图文匹配准确率85%，标签召回率70%，精确率80%。我们通过定期抽样人工复核确保评测质量，严禁编造数据。”
:::

::: warning ⚠️ 连环追问与高分续答
- **追问 1**：如何处理图文部分匹配（如图片展示穿搭，文本讲护肤）的情况？
  - **续答**：我们引入细粒度匹配：将图文分别拆分为实体（如服装、护肤品），计算实体级匹配度，再综合评分。对于部分匹配，标注为“弱相关”，并在标签生成时分别处理。
:::

::: details 🛠️ 换成你自己的项目时改这三处
1. 根据自身内容类型（如短视频、直播），调整多模态评测维度（如时序一致性）。
2. 引入用户交互数据（如点赞、收藏）作为弱监督信号，辅助评测。
3. 设计自动化评测流水线，定期用新数据更新评测集。
:::
