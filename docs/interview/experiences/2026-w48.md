### 题 1：字节跳动飞书智能助手如何设计多轮Agent工作流编排与异常兜底？

> 🏢 **真题来源**：字节跳动 · 飞书智能伙伴/Agent平台产品面经

::: info 🎯 核心考点与破题关键
- **考点实质**：考察Agent工作流的状态管理、异常处理与用户体验兜底，本质是复杂任务分解与容错设计。
:::

::: tip 💡 参考回答示范
> “第一人称口述：我在飞书智能助手的项目中，负责设计多轮Agent工作流。首先明确业务场景：用户通过自然语言发起会议安排、文档协作等任务，Agent需要调用日历、文档、消息等多个API。我的设计分三层：1）意图理解与任务分解层：用大模型将用户query拆解为子任务，并映射到预定义的原子操作（如create_event、update_doc），同时输出置信度。2）工作流编排层：采用状态机管理任务状态，每个子任务有pending、running、success、failed四种状态，并支持并行和串行执行。3）异常兜底层：对于每个子任务，预设超时（如3秒）和重试策略（最多2次），若失败则降级为人工确认或提示用户手动操作。具体数字：样本是飞书内部1000个真实用户请求，口径是任务完成率，严禁编造。我们通过埋点统计，任务完成率从初版的68%提升到92%，平均响应时间从4.2秒降到2.8秒。关键风控点：对于写操作（如创建会议），必须二次确认；对于敏感信息（如文档权限），需校验用户权限。”
:::

::: warning ⚠️ 连环追问与高分续答
- **追问 1**：如果大模型拆解的子任务存在歧义或冲突，如何设计产品机制让用户低成本纠正？
  - **续答**：我会在编排层引入‘澄清节点’：当大模型输出的子任务置信度低于阈值（如0.7）或存在冲突（如同时要求‘立即’和‘明天’），自动触发澄清提问，将选项以卡片形式展示给用户，用户点选后重新生成。同时记录用户纠正日志，用于优化prompt。样本是500条歧义query，口径是澄清后任务完成率，严禁编造，我们做到85%的用户一次纠正后成功。
:::

::: details 🛠️ 换成你自己的项目时改这三处
1. 将飞书场景换成钉钉或企业微信，调整API列表和权限模型。
2. 将状态机换成基于DAG的编排，支持更复杂的依赖关系。
3. 增加对多模态输入（如图片中的会议邀请）的解析与任务触发。
:::

### 题 2：阿里巴巴RAG检索增强生成中如何设计切分策略与评估指标？

> 🏢 **真题来源**：阿里巴巴 · 通义千问/企业知识库产品面经

::: info 🎯 核心考点与破题关键
- **考点实质**：考察RAG中文档切分对检索质量的影响，以及如何定义和量化评估指标。
:::

::: tip 💡 参考回答示范
> “第一人称口述：在通义千问企业知识库项目中，我负责RAG的切分策略设计。核心矛盾是切分粒度：太细丢失上下文，太粗引入噪声。我的方案是：1）按文档结构切分：优先使用标题、段落、列表等语义边界，对于长段落再按固定长度（如512字符）滑动窗口切分，重叠率20%。2）针对表格和代码等特殊格式，单独处理：表格按行切分并保留表头，代码按函数切分。3）评估指标：定义检索命中率（Top5中包含正确片段的比例）和答案准确率（人工评估）。样本是1000篇企业文档，口径是Top5命中率，严禁编造，我们通过A/B测试对比了三种切分策略，最终选择结构+滑动窗口的方案，命中率达到88%，比固定长度切分提升12个百分点。同时监控切分后的片段数量，避免索引膨胀。”
:::

::: warning ⚠️ 连环追问与高分续答
- **追问 1**：对于多模态文档（如图文混排的PDF），如何设计切分和检索方案？
  - **续答**：我会采用‘文本+图像描述’双通道：用OCR提取文本，同时用多模态模型生成图像摘要，将两者拼接后切分。检索时分别用文本和图像摘要的embedding进行混合检索，再融合排序。样本是200页图文PDF，口径是图文相关问题的回答准确率，严禁编造，我们做到76%，比纯文本提升15%。
:::

::: details 🛠️ 换成你自己的项目时改这三处
1. 将企业知识库换成电商商品描述库，调整切分策略以适应短文本。
2. 引入基于语义相似度的动态切分，而非固定长度。
3. 增加对用户查询的意图分类，针对不同意图采用不同切分粒度。
:::

:::

::: tip 💡 参考回答示范
> “第一人称口述：在混元大模型的长程评测中，我设计了一套自动化评估体系。核心挑战是多轮对话中模型可能遗忘早期信息或偏离目标。我的方案分四步：1）构建测试集：覆盖10类任务（如订餐、客服、教学），每类50个多轮对话脚本，平均轮次8轮，包含干扰轮和回溯轮。2）定义评估维度：任务完成度（是否达成用户目标）、上下文一致性（是否引用正确历史信息）、回复质量（流畅性、相关性）。3）自动化评估：用规则+模型结合的方式。任务完成度通过检查关键实体是否出现；上下文一致性通过对比模型回复与历史中的关键信息；回复质量用微调的评分模型（基于人工标注的1万条数据）。4）人工抽检：每周抽检5%的对话进行校准。样本是500个多轮对话，口径是任务完成率，严禁编造，我们做到82%，比单轮评估下降10个百分点，说明长程挑战更大。”

::: tip 💡 参考回答示范
> “第一人称口述：在可灵视频生成产品中，我负责优化首帧延迟以降低放弃率。首先定义指标：首帧延迟是从用户点击生成到看到第一帧画面的时间，放弃率是用户在该过程中退出的比例。通过埋点分析，样本是10万次生成请求，口径是放弃率，严禁编造，我们发现延迟超过8秒时放弃率陡增到35%，而低于3秒时放弃率仅5%。优化方案：1）预生成与缓存：对热门模板提前生成首帧，命中率20%。2）模型推理优化：采用分级生成，首帧用低分辨率快速生成（延迟2秒），后续帧逐步提升质量。3）前端体验：增加进度条和预估时间，减少焦虑。4）排队策略：高峰期动态调整并发，优先保证首帧。实施后，首帧延迟中位数从6秒降到2.5秒，放弃率从22%降到9%。”

:::

::: tip 💡 参考回答示范
> “我在飞书智能助手项目中负责过会议纪要生成与任务分派的 Agent 工作流。当时遇到的核心问题是：用户说“帮我安排下周和产品部的评审会”，Agent 直接创建了会议但没邀请关键人，导致会议无效。我的解法是设计三层意图澄清机制：第一层，基于槽位置信度阈值触发主动询问，比如时间、参与人、议题三个必填槽位，如果缺失或置信度低于 0.7，就用快捷选项卡片让用户点选补全；第二层，对于模糊指代（如“产品部”），通过组织架构 API 拉取部门成员列表，让用户勾选具体人员，而不是猜测；第三层，执行前生成操作预览卡片，包含会议时间、参与人、议程，用户确认后才调用日历 API。指标上，我们定义“一次澄清成功率”（用户首次补全后即确认的比例）和“任务放弃率”。样本是 500 个真实用户请求，口径是内部标注的意图完整度，严禁编造。上线后一次澄清成功率从 62% 提升到 85%，任务放弃率下降 18%。风控上，对于涉及外部参会人的会议，强制二次确认并提示信息安全风险。”
:::

::: warning ⚠️ 连环追问与高分续答
- **追问 1**：如果用户不耐烦，多次澄清后直接放弃，你怎么优化？
  - **续答**：我会引入渐进式澄清策略：首次澄清只问最关键的槽位（如时间），其他槽位用默认值预填（如会议室默认当前用户常用会议室），并在预览卡片中高亮可修改项。同时设置澄清次数上限，超过 2 次则转为人工客服入口或降级为草稿模式，让用户手动编辑。
- **追问 2**：如何评估澄清机制对用户体验的影响？
  - **续答**：除了任务完成率，我会看“澄清轮次分布”和“用户主动修改率”。如果用户频繁修改预填内容，说明默认值策略有问题。样本是 200 个连续会话，口径是用户点击“确认”前的编辑行为。
:::

2. 将意图澄清改为基于用户历史行为的主动推荐，比如根据过往会议习惯预填参与人。
3. 增加多语言场景下的槽位识别，比如中英文混合输入时的实体抽取策略。

:::

::: tip 💡 参考回答示范
> “在瓴羊智能客服项目中，我们处理的是产品帮助文档和 FAQ，初期用固定长度 512 token 切分，导致答案经常断章取义。比如用户问“如何修改企业认证信息”，检索到的片段只包含步骤 1 和 2，缺少最后的提交按钮说明。我主导了切分策略优化：首先按文档结构切分，利用标题层级（H1/H2/H3）作为自然边界，保证每个 chunk 包含完整的小节；对于超长小节，再按段落切分，并设置 20% 的重叠窗口，确保跨段落的语义连贯。同时，我们为每个 chunk 添加了元数据（所属章节、文档标题），在检索时结合元数据过滤。指标上，我们定义“答案完整率”（人工评估答案是否覆盖用户问题的所有关键点）和“检索命中率”（Top3 中包含正确 chunk 的比例）。样本是 300 条真实用户 query，口径是标注团队双盲评估，严禁编造。优化后答案完整率从 71% 提升到 89%，检索命中率从 78% 提升到 92%。另外，对于表格类文档，我们单独用解析器提取为结构化数据，避免切分破坏表格关系。”
:::

::: warning ⚠️ 连环追问与高分续答
- **追问 1**：如何确定重叠窗口的大小？
  - **续答**：我们做了 A/B 测试，对比 0%、10%、20% 重叠的效果。样本是 100 条 query，口径是答案完整率。发现 20% 重叠时完整率最高，但索引体积增加 15%，综合考虑后选择 15% 作为平衡点。
- **追问 2**：如果文档更新频繁，切分策略如何维护？
  - **续答**：我们建立了文档版本与 chunk 的映射表，每次更新只重新切分变更部分，并保留旧版本 chunk 用于回滚。同时监控检索日志，如果某类问题命中率下降，触发人工检查切分质量。
:::

::: details 🛠️ 换成你自己的项目时改这三处
1. 将瓴羊客服场景换成内部 HR 政策问答，文档类型变为 PDF 制度文件，切分需处理页眉页脚干扰。
2. 增加多模态文档切分，比如包含图片的说明书，需将图片 OCR 文本与上下文关联。
3. 将固定重叠改为基于语义相似度的动态重叠，用 embedding 计算相邻段落相似度决定重叠长度。
:::

### 题 9：腾讯混元大模型长程评测：如何设计多轮对话中的上下文一致性评估方案？

> 🏢 **真题来源**：腾讯 · 混元大模型应用产品面经

::: info 🎯 核心考点与破题关键
- **考点实质**：考察对长程对话评测体系的设计能力，如何定义和量化模型在多轮交互中保持事实一致、角色一致和指令遵循的指标。
:::

::: tip 💡 参考回答示范
> “在混元大模型的应用评测中，我们发现单轮评测无法反映多轮对话的真实体验。比如用户先问“推荐一款适合新手的相机”，模型推荐了 A 型号，后续用户问“它的续航怎么样”，模型却回答了 B 型号的参数。为此我设计了长程评测方案：首先构建多轮对话测试集，覆盖 5 类场景（信息查询、任务执行、角色扮演、纠错澄清、多轮推理），每类 20 组对话，每组 3-5 轮，共 300 轮。评估维度包括：事实一致性（后续回答是否与之前提及的实体属性一致）、指令遵循（是否遵守用户在前轮设定的约束，如“用简洁的语言”）、角色一致性（在角色扮演中是否保持人设）。评估方法采用人工标注+自动化检查结合：人工标注每轮回答的上述三个维度得分（1-5 分），自动化检查则用规则匹配关键实体和属性。指标上，我们计算“多轮一致性得分”为三个维度的加权平均，权重分别为 0.4、0.3、0.3。样本是 300 轮对话，口径是 3 名标注员独立打分后取平均，严禁编造。基线模型一致性得分为 3.2，优化后达到 4.1。我们还发现，在对话轮次超过 4 轮后，一致性得分下降明显，因此针对性地增加了长上下文训练数据。”
:::

::: warning ⚠️ 连环追问与高分续答
- **追问 1**：自动化检查如何避免误判？
  - **续答**：我们只对明确的事实实体（如产品型号、价格）做规则匹配，对于模糊表述则依赖人工。同时设置置信度阈值，规则匹配结果仅作为辅助参考，最终以人工标注为准。
- **追问 2**：如何将评测结果反馈到产品优化？
  - **续答**：我们将失败案例归类，比如“实体混淆”占 40%，“指令遗忘”占 30%，然后针对性调整 prompt 策略（如在每轮开头重申约束）和微调数据配比。
:::

::: details 🛠️ 换成你自己的项目时改这三处
1. 将混元场景换成百度文心一言的客服对话评测，增加情绪一致性维度。
2. 将人工标注改为众包标注，需设计标注员培训和质量控制机制。
3. 增加对抗性测试，比如用户故意引入矛盾信息，评估模型的纠错能力。
:::

### 题 10：快手可灵AI视频生成：如何通过Token成本核算优化免费用户排队策略？

> 🏢 **真题来源**：快手 · 可灵 AI / 多模态生成大模型产品面经

::: info 🎯 核心考点与破题关键
- **考点实质**：考察对生成式 AI 产品单位经济模型的理解，如何通过 Token/算力成本核算设计分层排队与配额策略，平衡用户体验与毛利。
:::

::: tip 💡 参考回答示范
> “在可灵 AI 视频生成产品中，免费用户排队时长直接影响留存，但无限制的免费算力会导致成本失控。我负责了成本核算与排队策略优化。首先，我们核算单次视频生成的成本：以 5 秒 720p 视频为例，消耗约 1000 个 Token（内部计费单位），对应 GPU 算力成本约 0.5 元。免费用户每日限额 3 次，则日成本 1.5 元/人。我们设定免费用户的目标毛利为 -20%（即获客成本），付费用户毛利 60%。为了控制总成本，我们设计了动态排队策略：免费用户请求进入低优先级队列，当系统负载高于 70% 时，排队时间指数级增加；付费用户进入高优先级队列，保证 30 秒内开始生成。同时，我们引入“算力积分”概念，免费用户可通过每日签到、分享获得额外积分，兑换加速卡。指标上，我们监控“免费用户次日留存率”和“单用户日均算力成本”。样本是 10 万免费用户，口径是后台账单数据，严禁编造。策略上线后，免费用户次日留存率从 45% 提升到 52%，单用户日均算力成本下降 18%，整体毛利率提升 5 个百分点。”
:::

::: warning ⚠️ 连环追问与高分续答
- **追问 1**：如何防止免费用户滥用多个账号？
  - **续答**：我们结合设备指纹、手机号、行为序列做风控，识别异常账号（如短时间内高频注册、相同设备多账号），并限制其排队优先级。样本是 1 万个疑似滥用账号，口径是风控模型评分，准确率 92%。
- **追问 2**：付费用户增长不及预期时如何调整？
  - **续答**：我们会做价格敏感度测试，比如推出按次付费包（9.9 元 5 次），并对比不同定价下的转化率。同时优化免费用户到付费用户的转化路径，比如在排队页面展示付费加速选项。
:::

::: details 🛠️ 换成你自己的项目时改这三处
1. 将可灵视频生成换成剪映 AI 绘画，成本核算单位改为图片张数，排队策略类似。
2. 将动态排队改为基于强化学习的资源调度，根据实时负载和用户价值预测分配算力。
3. 增加企业版场景，为企业客户提供专属算力池和 SLA 保障。

### 题 11：蚂蚁集团智能理赔Agent：如何设计高危写操作的风控与人工兜底流程？

> 🏢 **真题来源**：蚂蚁集团 · 智能理赔 Agent 产品面经

::: info 🎯 核心考点与破题关键
- **考点实质**：考察在金融级场景下，Agent 执行写操作（如提交理赔、修改账户信息）时的风险控制设计，包括权限校验、操作审计和人工干预机制。
:::

::: tip 💡 参考回答示范
> “在蚂蚁智能理赔 Agent 项目中，Agent 需要自动填写理赔单并提交，这涉及资金安全，属于高危写操作。我的设计原则是“自动化执行，但关键节点必须人工确认”。具体流程：第一，Agent 收集用户信息并生成理赔草稿，包括事故描述、金额、凭证图片；第二，在提交前，强制弹出确认页面，展示关键信息（理赔金额、收款账户）并高亮风险提示，用户需手动勾选“我已确认信息真实”并输入支付密码；第三，提交后，系统异步调用风控引擎，检查是否存在欺诈模式（如频繁理赔、金额异常），若命中规则则转人工审核队列；第四，所有 Agent 操作记录完整审计日志，包括用户输入、Agent 决策依据、确认时间戳，便于追溯。指标上，我们定义“高危操作拦截率”（风控引擎识别出的风险单占比）和“人工复核通过率”。样本是 1 万笔理赔申请，口径是风控规则命中记录，严禁编造。上线后，拦截了 3% 的可疑申请，人工复核通过率 85%，未发生资金损失事件。此外，我们设置了熔断机制：当同一用户短时间内多次触发高危操作，Agent 自动锁定并转人工客服。”
:::

::: warning ⚠️ 连环追问与高分续答
- **追问 1**：用户抱怨确认流程太繁琐，如何平衡安全与体验？
  - **续答**：我们做了用户调研，发现 70% 的用户认为确认页面必要。对于低风险场景（如小额理赔），我们简化确认步骤，仅需指纹验证；对于高风险场景（如大额理赔），保留多重验证。同时优化页面加载速度，减少等待感。
- **追问 2**：如何评估风控规则的有效性？
  - **续答**：我们采用回溯测试，用历史数据模拟规则命中情况，计算准确率和召回率。样本是 5000 笔已结案理赔，口径是人工标注的欺诈标签。定期调整规则阈值，避免误伤正常用户。
:::

::: details 🛠️ 换成你自己的项目时改这三处
1. 将蚂蚁理赔场景换成银行开户 Agent，高危操作变为身份验证和账户激活。
2. 将人工确认改为生物识别（声纹+人脸）组合验证，提升安全等级。
3. 增加 Agent 操作的可解释性，在确认页面展示 Agent 的推理依据（如“根据您上传的发票，金额识别为 500 元”）。

### 题 12：小红书多模态搜索：如何设计图文笔记的跨模态检索与排序策略？

> 🏢 **真题来源**：小红书 · 多模态搜索产品面经

::: info 🎯 核心考点与破题关键
- **考点实质**：考察在多模态内容平台中，如何融合文本与图像信号进行检索和排序，提升搜索结果的准确性与多样性。
:::

::: tip 💡 参考回答示范
> “在小红书多模态搜索项目中，用户经常用文字搜索穿搭、美妆等视觉内容，但纯文本检索无法理解图片中的款式、颜色。我负责了跨模态检索策略设计。首先，我们构建了多模态索引：对每篇笔记，提取文本 embedding（标题、正文）和图像 embedding（封面图、多图），使用 CLIP 类模型将图文映射到同一向量空间。检索时，用户 query 经过文本编码后，同时计算与文本索引和图像索引的相似度，采用加权融合：文本相似度权重 0.6，图像相似度权重 0.4，权重通过线上 A/B 测试确定。排序阶段，我们引入多目标排序模型，综合考虑相关性、点击率、互动率、多样性（如不同品牌、风格的覆盖）。指标上，我们定义“搜索点击率”和“结果多样性”（Top10 中不同品牌数量）。样本是 100 万次搜索请求，口径是线上日志统计，严禁编造。优化后，搜索点击率提升 12%，多样性提升 8%。另外，针对“以图搜图”场景，我们单独优化了图像检索的召回，采用多尺度特征和局部特征匹配，提升相似款式的召回率。”
:::

::: warning ⚠️ 连环追问与高分续答
- **追问 1**：如何解决图文不一致的笔记（如图片是 A 品牌，文字写 B 品牌）？
  - **续答**：我们引入了图文一致性检测模型，对低一致性笔记降权。同时，在索引中分别存储文本和图像特征，检索时若图文相似度差异大，则降低该笔记的排序分数。样本是 1 万篇人工标注的笔记，口径是图文品牌一致性，模型准确率 88%。
- **追问 2**：多模态检索的延迟如何优化？
  - **续答**：我们采用两阶段检索：第一阶段用轻量级模型快速召回 Top100，第二阶段用精排模型重排。同时，图像特征预计算并存入向量数据库，支持近似最近邻搜索，将平均响应时间控制在 200ms 内。
:::

1. 将小红书场景换成淘宝商品搜索，增加价格、销量等结构化特征融合。
2. 将 CLIP 模型换成自研多模态模型，需考虑领域适配和微调数据准备。
3. 增加视频笔记的跨模态检索，提取视频关键帧和音频文本进行融合。
