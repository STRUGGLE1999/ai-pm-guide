### 题 1：字节跳动飞书智能助手如何设计多轮Agent工作流编排以降低误操作率？

> 🏢 **真题来源**：字节跳动 · 飞书 AI / 企业协同 Agent 产品面经

::: info 🎯 核心考点与破题关键
- **考点实质**：Agent 工作流编排中状态管理与人工确认节点的设计，平衡自动化效率与操作风险。
:::

::: tip 💡 参考回答示范
> “第一人称口述：我在设计飞书智能助手处理“会议纪要自动生成并分发”任务时，把工作流拆成感知、规划、执行、确认四层。感知层用规则+小模型抽取指令意图，样本是近3个月2000条真实用户指令，口径是意图分类准确率需≥92%。规划层用LLM生成步骤树，但限制最大深度为5步，避免无限循环。执行层对写操作（如发消息、改日程）强制插入人工确认节点，确认率100%。确认节点设计成卡片形式，展示操作摘要和影响范围，用户点“确认”才执行。风控上，对高危操作如删除文档、批量@人，额外要求二次验证。指标上，误操作率从初版的8%降到1.2%，任务完成率从65%提升到89%。关键取舍是自动化率与安全性的平衡，我们宁可多一次确认也不冒误操作风险。”
:::

::: warning ⚠️ 连环追问与高分续答
- **追问 1**：如果用户嫌确认节点太繁琐，要求一键执行所有操作，你怎么处理？
  - **续答**：我会做分级策略：低危操作（如创建待办）默认自动执行，中危（如发消息给单人）可配置免确认，高危（如群发、删除）强制确认。同时提供“信任模式”开关，但开启时需用户二次授权并记录审计日志。样本上，我们灰度了10%用户，口径是开启信任模式后误操作率上升不超过0.5%才全量。
:::

::: details 🛠️ 换成你自己的项目时改这三处
1. 换成自己项目时，把飞书场景改为钉钉审批流，确认节点设计为审批卡片。
2. 指标口径改为任务平均耗时和用户NPS，样本用自己产品的埋点数据。
3. 风控策略增加操作回滚机制，如5分钟内可撤销。
:::

### 题 2：阿里巴巴RAG检索中如何设计切分策略以平衡召回率与生成质量？

> 🏢 **真题来源**：阿里巴巴 · 通义千问 / 企业知识库 RAG 产品面经

::: info 🎯 核心考点与破题关键
- **考点实质**：文档切分粒度对检索召回和LLM上下文有效利用的影响，需结合业务文档类型做动态切分。
:::

::: tip 💡 参考回答示范
> “第一人称口述：在通义千问企业知识库项目中，我负责RAG切分策略。我们面对的是产品手册、合同、FAQ三类文档。初期用固定512字符切分，样本是5000份文档，口径是召回率@10为78%，但生成答案完整率只有62%，因为切分截断了表格和条款。后来改为语义切分：先用小模型识别段落边界和表格区域，表格整体作为一个块，段落按标题层级切，块大小动态在256-1024字符。同时保留父子块关系，检索时用子块召回，生成时用父块补充上下文。调整后召回率@10提升到85%，答案完整率到81%。对于合同类，我们额外加条款编号索引，确保引用准确。指标上还监控了切分块的平均长度和重复率，避免过度切分。”
:::

::: warning ⚠️ 连环追问与高分续答
- **追问 1**：语义切分依赖小模型，如果小模型误判边界导致切分错误，如何兜底？
  - **续答**：我们设了规则兜底：检测到连续两个块长度差异超过3倍或块内出现未闭合的括号/表格标记时，触发人工规则切分。同时记录误判样本，每周迭代小模型。样本上，误判率从初版的12%降到4%，口径是人工抽检200个块。
:::

::: details 🛠️ 换成你自己的项目时改这三处
1. 换成自己项目时，文档类型改为法律文书，切分策略增加条款级索引。
2. 指标改为答案准确率和引用溯源准确率，样本用自己业务的QA对。
3. 兜底策略增加基于LLM的切分质量打分，低于阈值重新切分。
:::

### 题 3：腾讯混元大模型长程评测如何设计多轮对话的自动化评估体系？

> 🏢 **真题来源**：腾讯 · 混元大模型 / 对话式 AI 产品面经

::: info 🎯 核心考点与破题关键
- **考点实质**：长程多轮对话中上下文一致性、任务完成度和安全性的自动化评测方法，需解决人工评估成本高的问题。
:::

::: tip 💡 参考回答示范
> “第一人称口述：在混元多轮对话评测中，我设计了三层评估体系。第一层是规则层，检查对话轮次、角色交替、敏感词，样本是1000组多轮对话，口径是规则通过率需≥99%。第二层是模型层，用微调后的评估模型对每轮回复打分，维度包括相关性、一致性、有用性，每维度1-5分。评估模型用人工标注的5000条数据训练，与人工评分相关性达到0.82。第三层是任务层，针对具体场景（如订票、客服）设计任务完成度检查点，用脚本模拟用户多轮交互，统计任务成功率。指标上，我们监控平均轮次得分、任务成功率、安全违规率。对于长程对话，特别关注第5轮后的得分衰减，衰减超过15%触发预警。自动化评估将评测周期从2周缩短到2天。”
:::

::: warning ⚠️ 连环追问与高分续答
- **追问 1**：评估模型本身可能有偏差，如何保证评估结果可信？
  - **续答**：我们做了三件事：一是定期用人工评估校准，每月抽200条对话对比；二是评估模型输出置信度，低置信度样本转人工；三是多评估模型投票，三个不同微调模型取平均。样本上，人工与自动评估的一致率从75%提升到88%。
:::

::: details 🛠️ 换成你自己的项目时改这三处
1. 换成自己项目时，场景改为金融客服，任务检查点增加合规话术检测。
2. 评估模型改为开源模型微调，降低成本和数据隐私风险。
3. 增加用户满意度模拟评分，用历史用户反馈训练。

### 题 4：百度文心一言Token成本算账：如何设计按场景分级的成本控制策略？

> 🏢 **真题来源**：百度 · 文心一言 / 大模型商业化产品面经

::: info 🎯 核心考点与破题关键
- **考点实质**：大模型API调用中Token消耗的成本结构分析与分级控制，确保产品毛利和用户体验平衡。
:::

::: tip 💡 参考回答示范
> “第一人称口述：在文心一言企业版中，我负责成本控制。首先算账：输入Token成本是0.008元/千Token，输出是0.012元/千Token，样本是日均100万次调用，口径是平均每次输入800Token、输出300Token，日成本约1.0万元。为控制成本，我设计场景分级：高频简单问答（如天气、常识）走小模型或缓存，成本降低70%；复杂创作走大模型但限制输出长度到500Token；长文档摘要用分段处理，避免一次性输入过长。同时设置用户级Token配额，超限降级到小模型。指标上，监控单次调用平均Token、缓存命中率、降级率。优化后日成本降低35%，用户满意度仅下降2%。关键是要做成本归因，按功能模块拆分Token消耗，找出浪费点。”
:::

::: warning ⚠️ 连环追问与高分续答
- **追问 1**：如果业务方要求所有请求都用大模型保证效果，你怎么说服他们接受分级策略？
  - **续答**：我会做A/B测试，样本选10%流量，口径是对比分级策略和大模型全量在任务完成率和用户留存上的差异。如果差异小于3%，用数据说服；如果差异大，则对高价值用户保留大模型，低价值用户分级，同时推动模型蒸馏降低小模型成本。
:::

::: details 🛠️ 换成你自己的项目时改这三处
1. 换成自己项目时，成本参数改为实际采购价，样本用自己产品的调用日志。
2. 分级策略增加基于用户付费等级的动态配额。
3. 指标增加毛利贡献和ROI计算。
:::

### 题 5：蚂蚁集团高危写操作风控：AI助手执行转账/删数据时如何设计确认与熔断机制？

> 🏢 **真题来源**：蚂蚁集团 · 智能助手 / 金融级 AI 产品面经

::: info 🎯 核心考点与破题关键
- **考点实质**：AI助手在金融场景执行高危写操作时的风险控制设计，包括意图确认、权限校验和实时熔断。
:::

::: tip 💡 参考回答示范
> “第一人称口述：在蚂蚁智能助手处理转账、删除账单等操作时，我设计了四道风控。第一，意图二次确认：用户说“转1000元给张三”，助手回复确认卡片，包含收款人、金额、账户，用户必须手动输入“确认”二字，不能语音确认。第二，权限校验：调用前检查用户账户状态、限额、收款人是否在白名单，样本是日均5万次转账请求，口径是拦截异常请求率需≥99.9%。第三，实时熔断：监控单用户高频操作，如1分钟内超过3次转账请求，自动冻结并转人工。第四，事后审计：所有高危操作记录操作日志和对话快照，保留180天。指标上，误操作率控制在0.01%以下，拦截欺诈尝试200+次/月。关键是确认环节不能省，且确认信息必须与执行信息完全一致。”

::: warning ⚠️ 连环追问与高分续答

:::

::: details 🛠️ 换成你自己的项目时改这三处
1. 换成自己项目时，高危操作改为删除数据库记录，确认方式改为二次密码。
2. 熔断规则改为基于时间窗口的动态阈值。
3. 审计日志增加区块链存证，确保不可篡改。

### 题 6：小红书多模态搜索：如何设计图文笔记的跨模态检索与生成答案？

> 🏢 **真题来源**：小红书 · 多模态搜索 / 社区 AI 产品面经

::: info 🎯 核心考点与破题关键
- **考点实质**：图文混合内容的多模态检索中，如何对齐图像与文本语义，并生成结构化答案。
:::

::: tip 💡 参考回答示范
> “第一人称口述：在小红书多模态搜索项目中，我负责图文笔记的检索与答案生成。用户上传一张穿搭图片，问“类似风格怎么搭”。我们先用CLIP模型提取图片向量，与笔记图片向量做相似检索，样本是100万篇笔记，口径是Top50召回的相关性人工评分≥4分（5分制）。同时用OCR提取图片中的文字（如品牌、颜色），补充到文本检索。检索结果用多模态LLM生成答案，输入是用户图片+Top5笔记的图文对，输出搭配建议。指标上，答案有用率从初版的60%提升到78%，用户点击率提升12%。难点是跨模态对齐，我们通过对比学习微调CLIP，让图文向量在同一个空间更接近。另外，生成答案时要求引用具体笔记，避免编造。”
:::

::: warning ⚠️ 连环追问与高分续答
- **追问 1**：如果用户上传的图片是模糊的或非时尚类，如何避免检索到不相关笔记？
  - **续答**：我们设了置信度阈值，CLIP相似度低于0.6时触发澄清提问，让用户补充文字描述或重新上传。同时用图像分类模型判断图片类别，非时尚类走通用搜索。样本上，误检率从15%降到5%。
:::

::: details 🛠️ 换成你自己的项目时改这三处
1. 换成自己项目时，场景改为家居装修图文搜索，检索库改为商品库。
2. 生成答案改为结构化模板，如“风格+单品+购买链接”。
3. 指标增加答案多样性评估，避免总是推荐同几篇笔记。

### 题 7：字节跳动飞书智能助手：如何设计Agent工作流处理跨文档数据汇总与自动周报生成？

::: info 🎯 核心考点与破题关键
- **考点实质**：考察Agent多步任务编排、工具调用可靠性、长上下文信息整合及用户意图理解。
:::

::: tip 💡 参考回答示范
> “我会从用户真实场景出发。飞书用户需要每周从多个文档、表格、聊天记录中提取关键进展，生成结构化周报。我的设计分四层：第一，意图解析层，用LLM将用户自然语言指令拆解为子任务，比如‘汇总本周项目A的进展’需要检索文档、表格和聊天。第二，工具编排层，定义原子工具如search_docs、read_sheet、summarize_chat，每个工具带参数schema和超时重试策略。第三，执行层，采用ReAct模式，让Agent根据中间结果决定下一步，但设置最大步数限制（如10步）防止死循环。第四，结果合成层，用模板约束输出格式，并附上引用来源链接。关键指标：任务成功率（样本是100条真实周报请求，口径是人工评估完全正确）、平均耗时（目标<30秒）、工具调用错误率（<5%）。风控方面：对敏感文档（如HR绩效）做权限校验，Agent无权访问则跳过并提示；对生成内容做事实一致性检查，引用原文片段。”
:::

::: warning ⚠️ 连环追问与高分续答
- **追问 1**：如果Agent在检索时发现多个同名文档，如何确保选对？
  - **续答**：我会在工具返回结果中增加元数据排序：最近修改时间、用户最近访问频率、文档所在文件夹权限。同时让Agent在不确定时向用户发起澄清提问，而不是盲目选择。样本是50个歧义场景，口径是人工判断Agent选择正确或主动澄清的比例，目标>90%。
- **追问 2**：如何评估周报生成的质量？
  - **续答**：设计三级评估：第一，关键信息覆盖率，人工标注每份周报应包含的要点，计算召回；第二，事实准确性，检查生成内容是否与源文档一致，用NLI模型辅助判断；第三，用户采纳率，上线后统计用户直接发送或仅微调后发送的比例。初期样本200份，口径是人工评分，目标覆盖率>85%，准确率>95%。
:::

::: details 🛠️ 换成你自己的项目时改这三处
1. 将飞书文档替换为钉钉文档或企业微信微盘，工具调用API不同但编排逻辑类似。
2. 将周报生成场景改为会议纪要自动生成待办，重点考察从非结构化对话中提取行动项。
3. 增加多轮修改能力，用户可对生成周报提出‘更简洁’等反馈，Agent需迭代优化。

### 题 8：阿里巴巴瓴羊RAG：企业知识库问答中，如何设计检索切分策略以平衡召回与精度？

> 🏢 **真题来源**：阿里巴巴 · 瓴羊 AI 产品面经

::: info 🎯 核心考点与破题关键
- **考点实质**：考察RAG中文档切分粒度、元数据过滤、混合检索及重排序的工程权衡。
:::

::: tip 💡 参考回答示范
> “在瓴羊企业知识库场景，文档类型多样（产品手册、FAQ、合同），我的切分策略是动态的：第一，按文档结构切分，利用标题层级和段落边界，优先在章节处切分，避免切断语义。第二，设置块大小上限（如512 token）和重叠窗口（如50 token），保证上下文连贯。第三，为每个块附加元数据：来源文档、章节路径、更新时间、权限标签。检索时采用混合策略：先用BM25做关键词召回，再用向量检索做语义召回，然后通过元数据过滤（如只检索用户有权限的文档），最后用交叉编码器重排序Top 20。指标上，样本是500条真实用户问题，口径是人工标注答案所在块，评估Recall@10和MRR。目标Recall@10>90%，MRR>0.7。风控：对合同等敏感文档，切分后仍保留原文链接，答案必须引用原文片段，避免模型幻觉。”

::: warning ⚠️ 连环追问与高分续答

::: tip 💡 参考回答示范
> “在混元大模型评测项目中，我负责设计长程评测体系。传统单轮评测无法反映多轮对话中的上下文保持和逻辑连贯性。我们构建了三层评测：第一层是单轮基础能力，覆盖知识问答、数学推理、代码生成，使用公开基准如 MMLU、GSM8K；第二层是多轮对话评测，构造 200 组多轮对话样本，每组 5-10 轮，评估指标包括上下文一致性（是否遗忘之前信息）、话题转移合理性、指代消解准确率；第三层是复杂推理评测，设计需要多步推理的任务，如“根据三份财报计算复合增长率并给出投资建议”，评估推理链完整性和结论正确性。样本是 200 组多轮对话和 100 个复杂推理任务，口径是“一致性得分 = 人工评估每轮回答与历史对话不矛盾的比例”，严禁编造，我们实测混元在一致性上达到 92%。自动化评估采用 GPT-4 作为裁判，但需人工抽检 10% 校准。”
:::

::: warning ⚠️ 连环追问与高分续答
- **追问 1**：如何避免 GPT-4 裁判的偏见？
  - **续答**：我采取三种措施：一是设计细粒度评分 rubric，要求裁判按维度打分（如相关性、准确性、完整性），而不是整体打分；二是人工标注 200 条样本作为黄金标准，计算裁判与人工的一致性（Cohen's kappa），低于 0.7 则调整 prompt；三是引入双裁判机制，两个不同模型裁判结果不一致时转人工。样本是 200 条，口径是“一致性系数”，严禁编造，我们校准后 kappa 达到 0.82。
:::

::: details 🛠️ 换成你自己的项目时改这三处
1. 将混元换成其他大模型，调整评测基准以匹配模型能力特点。
2. 把多轮对话场景换成客服场景，增加情绪识别和问题解决率指标。
3. 复杂推理任务改为代码调试，评估模型定位 bug 和修复的能力。
:::

### 题 16：美团到店业务大模型应用如何核算 Token 成本并设计降本方案？

> 🏢 **真题来源**：美团 · 到店 AI 应用 / 成本优化产品面经

::: info 🎯 核心考点与破题关键
- **考点实质**：考察对 LLM 调用成本结构的理解、成本分摊模型设计以及产品侧降本策略（如缓存、精简 prompt、模型选型）的能力。
:::

::: tip 💡 参考回答示范
> “在美团到店智能客服项目中，我负责 Token 成本核算与优化。首先建立成本口径：单次会话成本 = （输入 token 数 × 输入单价 + 输出 token 数 × 输出单价）/ 1000。样本是 10 万次真实会话，口径是“平均单次会话成本”，严禁编造，我们实测使用 GPT-3.5 时平均成本为 0.12 元/次。成本分摊到业务线按会话来源标记。降本方案分三层：第一层是 prompt 精简，去除冗余示例和重复指令，将平均输入 token 从 800 降到 500；第二层是缓存高频问答，对 Top 100 常见问题（占会话量 40%）建立缓存，直接返回结果，成本降为 0；第三层是模型分级，简单意图识别用小模型（如 7B 模型），复杂生成用大模型。综合后单次成本降至 0.05 元/次。同时设置成本监控看板，按业务线日维度预警。”
:::

::: warning ⚠️ 连环追问与高分续答
- **追问 1**：缓存命中率下降时如何应对？
  - **续答**：我会分析缓存未命中的 query，发现长尾问题增多。策略是：一是扩大缓存范围，但设置相似度阈值（如 0.9）进行语义缓存；二是对未命中 query 聚类，定期挖掘新的高频问题加入缓存；三是动态调整缓存 TTL，对时效性强的问题（如促销活动）缩短 TTL。样本是 1 万条未命中 query，口径是“缓存命中率 = 命中次数 / 总请求数”，严禁编造，我们通过语义缓存将命中率从 40% 提升到 55%。
:::

::: details 🛠️ 换成你自己的项目时改这三处
1. 将美团到店场景换成电商商品描述生成，成本核算按生成次数和 token 数。
2. 模型选型从 GPT-3.5 换为国产大模型，重新计算单价和效果平衡点。
3. 增加流式输出的成本影响评估，因流式输出可能增加 token 消耗。
:::

### 题 17：蚂蚁集团智能理财助手如何设计高危写操作的风控与确认机制？

> 🏢 **真题来源**：蚂蚁集团 · 智能理财 / 安全产品面经

::: info 🎯 核心考点与破题关键
- **考点实质**：考察对金融场景下 AI 助手执行转账、购买理财等高危操作的风险识别、多级确认、可追溯审计的产品设计能力。
:::

::: tip 💡 参考回答示范
> “在蚂蚁智能理财助手项目中，我负责高危写操作的风控设计。高危操作定义为涉及资金变动、产品购买、个人信息修改等。我们设计四层防护：第一层是意图识别与风险分级，通过规则+模型判断操作风险等级，如转账超过 1 万元为高风险；第二层是强制二次确认，高风险操作必须通过弹窗展示交易详情（金额、收款方、产品风险等级），并要求用户手动输入“确认”或使用生物识别；第三层是额度与频次限制，单日累计转账限额 5 万元，单产品购买限额 10 万元，超限则转人工；第四层是全链路审计，记录用户意图、AI 建议、用户确认动作、最终结果，保存 5 年。样本是 1 万次高危操作请求，口径是“误操作率 = 用户投诉或撤销的比例”，严禁编造，我们实测误操作率从 0.5% 降至 0.1%。同时设置冷静期：高风险操作完成后 15 分钟内可撤销。”
:::

::: warning ⚠️ 连环追问与高分续答
- **追问 1**：如何平衡风控与用户体验，避免过度打扰？
  - **续答**：我采用动态风控策略：对低风险操作（如 100 元以下转账）仅需一次确认；对中风险操作（100-1000 元）使用滑动确认；对高风险操作才要求生物识别。同时根据用户历史行为建立信任分，信任分高的用户可适当放宽频次限制。样本是 5000 名用户，口径是“用户满意度 = 操作完成率 × 确认步骤数倒数”，严禁编造，我们通过 A/B 测试找到平衡点，满意度提升 15%。
:::

::: details 🛠️ 换成你自己的项目时改这三处
1. 将理财场景换成医疗问诊助手，高危操作改为预约挂号、药品购买，风控重点为药品禁忌症提醒。
2. 把生物识别确认换成短信验证码+人脸识别双因子。
3. 审计日志对接企业合规系统，增加自动生成合规报告功能。
:::

### 题 18：小红书多模态内容理解如何设计图文匹配评测以提升搜索相关性？

> 🏢 **真题来源**：小红书 · 多模态搜索 / 内容理解产品面经

::: info 🎯 核心考点与破题关键
- **考点实质**：考察对多模态模型评测指标设计、数据构造、badcase 分析的能力，本质是解决图文语义对齐和搜索意图匹配的量化评估问题。
:::

::: tip 💡 参考回答示范
> “在小红书多模态搜索项目中，我负责图文匹配评测体系设计。目标是通过评测驱动模型迭代，提升搜索相关性。我们构建了包含 5000 组图文对的评测集，每组包含一张图片、标题、正文和用户搜索 query。评测指标分三个维度：第一是图文一致性，判断图片内容与文本描述是否匹配，采用人工标注 1-5 分；第二是 query-图文相关性，判断搜索结果是否满足搜索意图，采用分级标注（完全满足、部分满足、不满足）；第三是多样性，评估 top-10 结果是否覆盖不同角度。样本是 5000 组，口径是“相关性准确率 = 完全满足的 query 比例”，严禁编造，我们实测基线模型为 68%，优化后达到 79%。评测流程采用自动化初筛（用 CLIP 模型计算图文相似度，低于阈值转人工）+ 人工精标。”
:::

::: warning ⚠️ 连环追问与高分续答
- **追问 1**：如何降低人工标注成本？
  - **续答**：我采用主动学习策略：先用小模型对未标注数据预测，选择预测置信度低或模型分歧大的样本优先人工标注。同时设计半自动标注工具，预填模型预测结果，人工只需确认或修改。样本是 1 万组待标注数据，口径是“标注效率 = 每小时标注量”，严禁编造，我们从 50 组/小时提升到 120 组/小时。
:::

::: details 🛠️ 换成你自己的项目时改这三处
1. 将小红书场景换成电商商品主图与标题匹配评测，增加商品类目一致性指标。
2. 把 CLIP 模型换成更细粒度的多模态模型，如 BLIP-2，提升初筛准确率。
3. 增加视频内容的评测，抽取关键帧进行图文匹配评估。
:::
