# 业务价值、场景选型与 ROI 题库

在实际企业环境中，AI 项目死掉的最主要原因**不是算法效果不够惊艳，而是算不清经济账、找不到业务落地点、或者在数据合规上触礁**。
本题库考察 AI 产品经理的商业嗅觉、成本收益核算与企业级推进能力。

---

## 题目 1：如何判断一个业务场景究竟是“真需求”还是“为了用 AI 而用 AI 的伪需求”？

::: info 🎯 核心考察点与解题思路
- **考察意图**：考察候选人的业务理性。优秀的 AI PM 不盲目追逐技术热点，能够准确识别哪些场景用确定性代码更高效，哪些场景才真正需要 AI 的生成与泛化能力。
- **解题框架**：
  1. **痛点存在性与频次**：痛点是高频刚需还是低频伪命题？
  2. **传统方案替代成本**：如果用规则引擎、正则表达式、模板化脚本或传统搜索，成本与体验如何？
  3. **容错度与人机协同可行性**：当 AI 发生 5%~10% 的概率性错误时，业务能否承受？修复成本有多大？
  4. **经济模型可行性**：调用成本是否显著小于创造的价值？
:::

::: tip 💡 参考回答示范
> “在评估业务方或管理层提出的 AI 需求时，我坚持用 **‘价值三维筛选漏斗’** 进行严格过滤：
> 
> ```mermaid
> flowchart TD
>     A[业务痛点提出] --> B{1. 传统规则能否低成本解决？}
>     B -- 可以 --> B1[推荐传统工程/脚本方案，坚决不用大模型]
>     B -- 传统方案泛化差/规则爆炸 --> C{2. 错误代价是否业务可控？}
>     C -- 不可控且无人工校验兜底 --> C1[暂缓立项或收缩为纯辅助模式]
>     C -- 容错高或具备闭环校验 --> D{3. 边际收益是否远大于 Token 成本？}
>     D -- 算不过账 --> D1[打回重构业务场景]
>     D -- ROI 明确为正 --> E[批准立项进入 MVP]
> ```
> 
> **典型伪需求案例**：
> 比如业务方提出*‘用大模型帮财务做发票自动算税与报销审核’*。这通常是伪需求——算税是 100% 确定性的数学逻辑，用大模型既昂贵又存在算错风险，核心应该用 OCR 提取结构化数据 + 传统代码规则引擎校验。
> 
> **典型真需求案例**：
> 比如*‘售前方案工程师从海量非结构化历史招投标文档中快速提炼差异化方案草稿’*。这个场景非结构化程度极高、传统搜索无法综合语义、且人工初稿耗时数天，而 AI 能够在 5 分钟内生成框架，并由业务专家审核修改，人机协同价值极大，属于典型的高 ROI 真需求。”
:::

::: warning ⚠️ 踩坑提示与扣分点
- ❌ **扣分回答**：“只要技术上能跑通 Demo，就值得全面推给业务线使用。”（完全缺乏商业常识和成本意识）。
- 🔄 **高频追问**：*如果公司高管坚持要立项一个你判定为‘伪需求’的 AI 项目，作为产品经理你如何应对？*
:::

## 题目 2：如何向管理层/老板汇报 AI 项目的价值并科学测算 ROI？

::: info 🎯 核心考察点与解题思路
- **考察意图**：考察候选人将“技术指标（准确率、Token数）”翻译为“财务与经营指标（人效、节省工时、毛利率）”的商业汇报与量化建模能力。
- **解题框架**：
  1. **成本端（TCO，总拥有成本）**：API 调用费用 + 向量库/服务器云资源 + 研发运维人力 + 数据标注清洗成本。
  2. **收益端（Direct & Indirect Benefits）**：直接节省的工时成本（折算全职人力 FTE） + 业务增收/转化率提升 + 缩短的交付周期价值。
  3. **动态 ROI 计算公式**：$\text{ROI} = \frac{\text{年度业务总收益} - \text{年度总拥有成本 (TCO)}}{\text{年度总拥有成本 (TCO)}} \times 100\%$。
:::

::: tip 💡 参考回答示范
> “向管理层汇报 AI 项目时，我坚决不谈‘大模型多么智能、上下文有多长’，而是用管理层听得懂的 **‘财务与人效测算模型’** 汇报：
> 
> 以我们落地的‘AI 智能客服助手’为例，测算逻辑如下：
> 
> 1. **收益端（年度节约人力成本）**：
>    - 现状：一线客服团队 50 人，人均年综合成本 10 万元，年总支出 500 万元；
>    - AI 介入后：日常高频政策咨询自助解决率达到 35%，复杂工单处理时长从人均 8 分钟压缩至 4 分钟；
>    - 综合折算：相当于释放 **18 个全职人力（FTE）** 的工作量，直接节省人力工时折合 **180 万元/年**。
> 
> 2. **成本端（年度 TCO 总成本）**：
>    - Token 与 API 消耗：日均 3 万次会话，单次会话消耗约 2k Token，结合开源小模型路由与商业模型兜底，年 Token 成本约 **15 万元**；
>    - 服务器与向量数据库成本：约 **8 万元/年**；
>    - 数据治理与维护人力分摊：约 **12 万元/年**；
>    - 年度总支出：**35 万元/年**。
> 
> 3. **汇报结论**：
>    - **净收益**：$180万 - 35万 = 145 万元/年$；
>    - **项目年化 ROI**：$\frac{145}{35} \approx 414\%$；同时将客户平均响应时长从 30 秒降至 3 秒，NPS 提升 12 点。”
:::

::: warning ⚠️ 踩坑提示与扣分点
- ❌ **扣分回答**：只算 Token 费，忽略了服务器、向量库、日常数据清洗运营以及前期研发人力等隐性成本。
- 🔄 **高频追问**：*如果上线后实际节省的人力并没有直接裁员或减少编制，你如何向老板证明这个项目的实际收益？*
:::

## 题目 3：开源自部署模型（如 DeepSeek/Qwen）vs 闭源商用 API（如 OpenAI/Claude），企业落地如何选型？

::: info 🎯 核心考察点与解题思路
- **考察意图**：考察候选人对企业级 IT 架构、数据合规、高并发推理成本与演进策略的宏观把控能力。
- **解题框架**：从**数据隐私合规、调用成本临界点（Volume Break-even）、运维复杂度、能力上限与响应延迟**五个维度综合对比。
:::

::: tip 💡 参考回答示范
> “企业在开源自建与闭源 API 之间，绝不是非黑即白的选择，而是根据**‘业务并发规模、数据敏感度与任务复杂度’**动态演进：
> 
> | 选型考量维度 | 闭源商用 API（如 GPT-4o, Claude 3.5） | 开源自建部署（如 DeepSeek-R1, Qwen-2.5-72B） |
> | :--- | :--- | :--- |
> | **数据安全性** | 数据需出境或上传公有云，强监管行业（金融/政务）难以合规 | 数据完全内网物理隔离，满足等级保护与商业机密合规 |
> | **前期启动成本** | 零基础设施投入，按量付费，开箱即用 | 需采购昂贵的 GPU 算力卡（如 H800/A100）或租用私有云实例 |
> | **调用成本拐点** | 适合**低频、复杂任务或早期验证**；调用量过大时按 Token 计费极贵 | 适合**超高并发且任务固定**的场景；达到调用量拐点后单次推理成本远低于 API |
> | **定制与可控性** | 无法修改模型权重，受制于厂商接口限流与停服风险 | 可进行深度领域微调、量化剪枝与极致推理加速（vLLM） |
> 
> **推荐的落地策略（混合架构）**：
> - **初期/高价值复杂场景**：直接调用头部商用 API，以最快速度验证 PMF 与业务价值；
> - **成熟期/高并发敏感场景**：利用优质开源模型进行私有化部署，并将简单高频任务蒸馏至 7B/14B 小模型，实现数据安全与成本极致优化。”
:::

::: warning ⚠️ 踩坑提示与扣分点
- ❌ **常见误区**：“小公司或者刚起步的项目，为了绝对安全必须一上来就买几台 GPU 服务器自建部署。”（前期重资产投入极易导致项目中途夭折）。
- 🔄 **高频追问**：*在私有化部署开源模型时，如何评估需要采购多少张显卡与显存（VRAM）？*
:::

## 题目 4：B 端客户对数据隐私与合规极度顾虑，作为 AI 产品经理你如何给出令人信服的解决方案？

::: info 🎯 核心考察点与解题思路
- **考察意图**：考察对企业级安全、网络隔离、数据脱敏机制（PII Masking）与法律合规（如网信办大模型备案、数据安全法）的专业认知。
- **解题框架**：四重安全防护网（传输与存储加密 $\rightarrow$ 动态数据脱敏 $\rightarrow$ 零数据留存协议 $\rightarrow$ 混合部署/私有化交付）。
:::

::: tip 💡 参考回答示范
> “B 端客户的核心顾虑是**‘核心商业机密被大模型作为训练语料’**以及**‘敏感客户数据（PII）泄露’**。在方案设计中，我提供 **‘四重企业级安全防护体系’**：
> 
> 1. **商务与法务合规背书（Zero Data Retention）**：
>    选用具备企业级安全 SLA 的服务商通道（如 Azure OpenAI 或签署明确的零数据保留协议 ZDR），在合同中以法律条款明确承诺：*客户输入与输出数据绝不用于任何后续基础模型的训练或模型迭代*。
> 2. **网关层动态数据脱敏（PII Sanitization）**：
>    在请求离开企业内部网络前，部署专有安全网关。利用规则与轻量 NER 模型对身份证号、手机号、薪酬金额、核心代码变量名进行实时掩码替换（如 `张三` $\rightarrow$ `[User_A]`），大模型生成后再在本地进行还原。
> 3. **细粒度数据隔离与租户沙箱（Tenant Isolation）**：
>    知识库与向量数据库按租户甚至部门进行逻辑/物理隔离，严禁多租户向量索引混用，从底层物理杜绝数据串流越权。
> 4. **分级交付方案（满足不同预算与合规等级）**：
>    - **标准 SaaS 版**：企业公有云沙箱 + 数据加密传输与静态加密；
>    - **专有云/混合部署版**：敏感知识库留在客户内网，仅调用脱敏后的大模型推理；
>    - **纯私有化一体机版**：针对央国企、军工与金融核心业务，提供纯内网离线一体机软硬件交付。”
:::

::: warning ⚠️ 踩坑提示与扣分点
- ❌ **扣分回答**：“直接告诉客户大模型非常安全，绝对不会泄露，不用担心。”（空口无凭，无法通过企业客户的安全审查与 CISO 审批）。
- 🔄 **高频追问**：*如果国内大模型上线对外提供服务，在合规准入上需要完成哪些法定监管手续？（答：国家网信办大模型算法备案、生成式 AI 服务上线安全评估）。*
:::
